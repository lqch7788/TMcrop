## 二、Architecture Review (架构评审)

### 问题 1: JWT 认证中间件未应用 ✅ 已确认
**置信度**: 9/10
**文件**: `server/src/routes/index.ts`

**问题描述**: 
- JWT 认证中间件 `requireAuth` 已定义但未应用到任何路由
- 所有 API 端点公开访问，无需认证
- `apiClient.ts` 中 401 处理被注释掉

**现实影响**: 任何人可直接调用 API 获取/修改所有业务数据

**决策**: ✅ **启用 JWT 认证中间件**
- 将 `requireAuth` 应用到所有需要认证的路由
- 前端登录流程需要配合处理 token

---

### 问题 2: Route-DB 直接耦合 ✅ 已确认
**置信度**: 8/10
**文件**: `server/src/routes/*.ts`

**问题描述**:
- 路由直接导入并操作数据库
- 缺少 Service/Repository 层
- 表结构变化需要修改多个文件

**决策**: ✅ **引入 Service 层**
- 建议逐步重构，先从核心业务开始
- 可参考 `server/src/services/` 结构

---

### 问题 3: AuthSettingsContext 职责过多 ✅ 已确认
**置信度**: 7/10
**文件**: `src/contexts/AuthSettingsContext.tsx` (900+ 行)

**问题描述**:
- 一个 Context 处理组织、角色、用户、权限、部门、仓库、温室等 10+ 个关注点
- 违反单一职责原则
- 修改一个功能可能意外破坏其他功能

**决策**: ✅ **拆分为多个专用 Context**
- 建议按领域拆分: AuthContext, SettingsContext, OrganizationContext 等
- 便于单独测试和维护

---

### 问题 4: N+1 查询风险 ✅ 已确认
**置信度**: 6/10
**文件**: `src/services/*.ts`, `server/src/routes/*.ts`

**问题描述**:
- 获取列表时关联数据逐条加载
- 例如: `plantings.map(p => getCropVarietyById(p.cropVarietyId))`
- 缺少批量查询支持

**决策**: ✅ **优化 JOIN 查询**
- 使用 SQL JOIN 批量获取关联数据
- 在 Service 层实现批量加载

---

### 问题 5: 缺少组件级错误边界 ✅ 已确认
**置信度**: 7/10
**文件**: `src/App.tsx`

**问题描述**:
- 只有全局 ErrorBoundary
- 组件级错误导致整个页面崩溃
- 用户体验差

**决策**: ✅ **添加组件级错误边界**
- 为关键页面添加边界
- 使用 React Error Boundaries 模式
