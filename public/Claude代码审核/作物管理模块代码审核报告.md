### 2.2 重复代码导致数据不一致风险

**文件**: `src/services/cropInstanceService.ts:62-88`

```typescript
export function initInstances(): CropInstance[] {
  const stored = localStorage.getItem(STORAGE_KEY);
  if (stored) {
    try {
      return JSON.parse(stored);  // 与 getInstances 完全相同
    } catch {
      return defaultData;
    }
  }
  localStorage.setItem(STORAGE_KEY, JSON.stringify(defaultData));
  return defaultData;
}

export function getInstances(): CropInstance[] {
  const stored = localStorage.getItem(STORAGE_KEY);
  if (stored) {
    try {
      return JSON.parse(stored);  // 与 initInstances 完全相同
    } catch {
      return defaultData;
    }
  }
  return initInstances();  // 调用自身
}
```

**问题**: 两函数代码重复，违背 DRY 原则；任何修改需要同步两处。

**修复建议**: 重构为单一数据访问函数：
```typescript
function getStoredInstances(): CropInstance[] {
  const stored = localStorage.getItem(STORAGE_KEY);
  if (stored) {
    try {
      return JSON.parse(stored);
    } catch {
      return defaultData;
    }
  }
  return defaultData;
}

export function initInstances(): CropInstance[] {
  const stored = localStorage.getItem(STORAGE_KEY);
  if (!stored) {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(defaultData));
  }
  return getStoredInstances();
}

export function getInstances(): CropInstance[] {
  return getStoredInstances();
}
```

## 三、HIGH 问题（应该修复）

### 3.1 组件重复/架构问题 - Planting.tsx 与 CropVarietyManagement.tsx 功能重叠

**文件**: `src/pages/crop/Planting.tsx`

**问题**:
- `Planting.tsx` 是一个完整的作物管理页面实现（约 235 行代码）
- 而 `Harvest.tsx`、`Instance.tsx`、`Order.tsx`、`Seedling.tsx`、`SeedSource.tsx` 都是简单的 re-export
- 这意味着 `Planting.tsx` 是唯一包含实际代码的入口文件，但它只 re-export 了 `cropPage.tsx`
- 同时 `CropVarietyManagement.tsx` 实现了更完整的作物品种库管理功能

**影响**:
1. `Planting.tsx` 中的 `CropPage` 组件与 `CropVarietyManagement.tsx` 存在功能重叠
2. 入口文件职责不一致（5个是 re-export，1个是完整实现）
3. 可能导致路由冲突和维护困难

**修复建议**: 统一入口文件模式，所有页面都应该只是 re-export，不包含实现代码。

---

### 3.2 状态管理重复 - VarietyTree 和 CropVarietyTable 都有独立的状态管理

**文件**:
- `src/components/farm/crop-variety/VarietyTree.tsx:28-39`
- `src/components/farm/crop-variety/CropVarietyTable.tsx:37-47`

**问题**: 两个组件各自维护了独立的搜索状态，各自调用 `getCategoryOptions()` 获取数据。

**修复建议**: 将搜索/筛选状态提升到父组件 `CropVarietyManagement.tsx` 中统一管理。

---

### 3.3 硬编码状态值 - useVarietyTree.ts 存在副作用在 useMemo 中

**文件**: `src/components/farm/crop-variety/hooks/useVarietyTree.ts:459-463`

```typescript
// 错误：useMemo 中执行了 setState
useMemo(() => {
  const initialKeys = treeData.map(node => node.key);
  setExpandedKeys(new Set(initialKeys));
}, [treeData]);
```

**问题**: `useMemo` 的第一个参数是执行副作用的函数（设置 state），这违反了 React 的 hooks 规则。

**修复建议**: 改用 `useEffect` 来执行此初始化逻辑。

### 3.4 ID 生成使用 Date.now() 在高并发下不安全

**文件**: 多个服务文件

```typescript
// cropInstanceService.ts:152
id: 'CI' + Date.now(),

// cropOrderService.ts:99
id: 'CO' + Date.now(),

// plantingService.ts:131
id: 'PL' + Date.now(),

// seedlingService.ts:329
id: 'SD' + Date.now(),

// harvestService.ts:146
id: String(Date.now() + Math.random()),  // 更糟糕
```

**问题**: `Date.now()` 毫秒级精度，在快速连续操作时可能产生重复 ID。

**修复建议**: 使用 `crypto.randomUUID()` 或递增序列 + 时间戳组合。

---

### 3.5 API 封装层返回类型处理错误

**文件**: `src/services/apiCropInstanceService.ts:95-101`

```typescript
export async function updateInstance(id: string, updates: Partial<CropInstance>): Promise<CropInstance | null> {
  if (USE_API) {
    const result = await apiClient.put<{ id: string }>(`/crop-instances/${id}`, updates);
    return result ? { ...updates, id } as CropInstance : null;  // 错误！
  }
  return localService.updateInstance(id, updates);
}
```

**问题**: 返回的是 `updates` 对象的浅拷贝，而不是服务器返回的完整更新后对象。

**修复建议**:
```typescript
export async function updateInstance(id: string, updates: Partial<CropInstance>): Promise<CropInstance | null> {
  if (USE_API) {
    return apiClient.put<CropInstance>(`/crop-instances/${id}`, updates);
  }
  return localService.updateInstance(id, updates);
}
```

### 3.6 类型定义冲突 - 状态枚举重复定义

**修复建议**: 统一使用 `types/crop.ts` 中的 enum 定义，删除 `types/crop/planting.ts` 中的重复定义。
