# 作物全生命周期追踪系统设计

## 一、需求目标

实现从种源种苗入库 → 育苗 → 种植 → 采收入库 → 出库的完整数据追踪体系，确保：

1. **编码唯一性**：整个生命周期使用统一的作物批次编码，不重复
2. **数据关联**：各页面数据可相互关联追溯
3. **订单概念**：支持从种源开始建立"生产订单"，后续各环节可引用
4. **完整追溯**：从种源到成品出库的全程记录
5. **灵活来源**：支持多种种植来源，不强制要求全程内部流转

---

## 二、设计决策

| 决策项 | 选择 |
|--------|------|
| 作物编码粒度 | 批次/实例级别（不是品种级别） |
| 采收入库归属 | 移入作物管理模块（/crop/harvest） |
| 唯一性保障 | 创建独立的作物实例表（CropInstance） |

## 三、数据模型设计

### 3.1 作物实例表 (CropInstance) - 核心

```typescript
// 来源类型枚举（灵活支持多种来源）
type SourceOrigin =
  | 'internal_seed'       // 内部种源
  | 'external_purchase'   // 外部采购（种子/种苗）
  | 'tissue_culture'     // 组培苗
  | 'grafting'           // 嫁接苗
  | 'seedling_split'     // 分株繁殖
  | 'cutting'            // 扦插繁殖
  | 'direct_seedling'     // 直接育苗（自繁）
  | 'direct_planting'     // 直接种植（外购苗）

interface CropInstance {
  id: string;                    // 唯一ID
  instanceCode: string;           // 实例编码 = 品种编码(9位) + 年月日(6位) + 流水号(3位)
                                  // 示例: PD0301000100240426001 (红果番茄 2024年4月26日 第001批)
  orderId: string;               // 关联的订单ID（可为空）
  orderCode: string;             // 关联的订单编号

  // 作物基本信息（来自品种编码）
  cropCategory: string;           // 作物类别
  cropName: string;              // 作物名称
  cropVariety: string;            // 作物品种
  categoryCode: string;           // 大类代码 (PD)
  typeCode: string;               // 类型代码 (03)
  subCode: string;                // 品种代码 (01)

  // 来源信息（灵活）
  sourceOrigin: SourceOrigin;     // 来源类型
  sourceDescription?: string;     // 来源描述（如：XX供应商，XX组培实验室）

  // 数量信息
  initialQuantity: number;        // 初始数量
  currentQuantity: number;        // 当前剩余数量
  plantedQuantity: number;       // 已定植数量
  harvestedQuantity: number;      // 已采收数量

  // 状态
  status: 'seedling' | 'planted' | 'growing' | 'harvested' | 'outbound' | 'cancelled';

  // 时间节点（根据来源类型，某些节点可能为空）
  seedEntryDate?: string;         // 种源入库日期（可选）
  seedlingStartDate?: string;     // 育苗开始日期（可选）
  plantingDate?: string;          // 定植日期（可选）
  harvestDate?: string;           // 首次采收日期（可选）
  outboundDate?: string;          // 出库日期（可选）

  // 溯源关系
  sourceInstanceId?: string;     // 来源实例ID（如果是育苗分株等繁殖方式）

  // 扩展信息
  createBy: string;
  createTime: string;
  updateTime: string;
}
```

### 来源类型说明

| 来源类型 | 说明 | 起始环节 |
|----------|------|----------|
| `internal_seed` | 内部种源入库 | 种源管理 |
| `external_purchase` | 外部采购的种子/种苗 | 种植管理（直接） |
| `tissue_culture` | 组培苗 | 育苗管理 |
| `grafting` | 嫁接苗 | 育苗管理 |
| `seedling_split` | 分株繁殖 | 育苗管理 |
| `cutting` | 扦插繁殖 | 育苗管理 |
| `direct_seedling` | 直接育苗（自繁） | 育苗管理 |
| `direct_planting` | 直接种植（外购苗） | 种植管理 |

### 关键约束

1. **实例可独立创建**：任何环节都可以创建新的作物实例
2. **关联可选**：可以先有无订单的实例，后续再关联
3. **状态独立**：时间节点根据实际发生的情况记录，不强制连续
4. **溯源可选**：只有繁殖类操作才需要填写 `sourceInstanceId`
5. **入库来源灵活**：
   - 内部采收入库（经过种植环节）
   - 外购成品入库（不经过内部种植环节，直接采购入库）
   - 外购种苗入库（直接采购种苗后种植）

### 5.2 编码生成规则

#### 实例编码规则
```
instanceCode = 品种编码(9位) + 年月日(6位) + 流水号(3位)
            = categoryCode(2) + typeCode(2) + subCode(2) + 年月日(6) + 流水号(3)
示例: PD0301000100240426001
```

#### 订单编码规则
```
orderCode = "DD" + 年月日(8位) + 流水号(3位)
示例: DD20240426001
```

## 八、验证方案

1. **编码唯一性验证**：同一天同一品种创建多条记录，验证编码不重复
2. **溯源验证**：从采收入库反查，验证能追溯到种源和订单
3. **数量一致性验证**：种源 → 育苗 → 种植 → 采收，数量递减正确
4. **路由验证**：采收入库新路径 `/crop/harvest` 可正常访问
5. **构建验证**：`npm run build` 成功
