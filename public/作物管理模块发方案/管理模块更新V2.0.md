# 种植管理系统迁移规划方案 V2.0

**文档版本：** V2.0
**编制日期：** 2026-04-26
**目标：** 用V1.1系统替代旧管理模块，保留旧功能并进行功能增强

---

## 一、项目背景与目标

### 1.1 背景
- **旧系统** (D:\iAGS\new): 农业物联网平台，使用 EJS + jQuery EasyUI，有6个管理页面
- **新系统** (V1.1): 基于 React + TypeScript + Ant Design 的现代农业管理系统
- **目标**: 用 V1.1 替代旧管理模块，保留旧功能并进行功能增强

### 1.2 旧系统6个管理页面
| 页面 | 功能 | V1.1现状 | 规划 |
|-----|------|---------|------|
| 种源管理 | 种子/种苗采购入库 | 缺失 | **新增** |
| 育苗管理 | 育苗批次和成苗率管理 | 缺失 | **新增** |
| 种植管理 | 区域种植记录管理 | 缺失 | **新增** |
| 施肥管理 | 施肥记录管理 | 已有农事管理 | 替代 |
| 产量管理 | 产量记录管理 | 已有采收入库 | 替代 |
| 采购商管理 | 供应商管理 | 已有供应商管理 | 替代 |

## 二、系统现状分析

### 2.1 旧系统核心数据结构

**种源管理**:
- seedCode (批号), cropName (作物), seedType (类型), supplierName (供应商)
- purchaseDate, quantity, unit, availableCount, pictures

**育苗管理**:
- seedlingCode (育苗批号), sourceCode (关联种源)
- cropName, seedlingType, siteName, startDate, endDate
- initialCount, survivalCount, survivalRate, lossRate, pictures

**种植管理**:
- plantCode (种植批号), seedlingCode (关联育苗)
- cropName, areaName, plantingCount, plantingDate
- soilPH, soilEC, isHarvest, harvestDate, lossRate, pictures

### 2.2 V1.1系统架构

```
技术栈: React 18.3 + TypeScript + Vite + Ant Design + Tailwind CSS
模式: 组件化开发 (types/data/components/pages)
路由: App.tsx
菜单: Sidebar.tsx
```

---

## 三、融合原则

| 原则 | 说明 |
|------|------|
| **数据优先** | 旧系统数据后续迁移，新系统直接复用 |
| **平滑过渡** | 逐步接管，不影响日常生产 |
| **风格统一** | 新增页面遵循V1.1 UI规范（Tailwind + Ant Design + 卡片式布局） |
| **功能增强** | 不只复制旧功能，要增加统计、分析、预警能力 |
| **复用最大化** | 已有模块能复用尽量复用 |

## 四、菜单与路由设计

### 4.1 方案: 新建"作物管理"主菜单

**理由**: 种源、育苗、种植是农业生产的前置环节，新建独立菜单更符合业务逻辑，便于后续扩展。

### 4.2 菜单结构

```
作物管理（新增主菜单）
├── 种源管理（新增）      → /crop/seed-source
├── 育苗管理（新增）      → /crop/seedling
└── 种植批次（新增）      → /crop/planting-batch
```

### 4.3 路由配置

```tsx
// App.tsx 新增路由
/crop/seed-source      → SeedSourcePage
/crop/seedling        → SeedlingPage
/crop/planting-batch   → PlantingBatchPage
/crop/planting-batch/:id → PlantingBatchDetail (详情页)
```

### 4.4 图标选择

使用 Lucide React 图标：
- 作物管理主菜单: `Leaf` 或 `Wheat`
- 种源管理: `Sprout`
- 育苗管理: `Flower2`
- 种植批次: `Trees`

## 五、数据模型设计

### 5.1 核心表结构

#### 种源表 tb_provenance

```sql
CREATE TABLE tb_provenance (
  id SERIAL PRIMARY KEY,
  code VARCHAR(64) NOT NULL UNIQUE COMMENT '种源编码',
  source_type VARCHAR(16) NOT NULL COMMENT '来源类型: seedling/seed',
  crop_type VARCHAR(32) COMMENT '作物类型',
  crop_name VARCHAR(32) NOT NULL COMMENT '作物名称',
  crop_variety VARCHAR(32) COMMENT '作物品种',
  supplier_id INT COMMENT '供应商ID',
  purchase_date DATE COMMENT '采购日期',
  quantity DECIMAL(10,2) NOT NULL COMMENT '登记数量',
  unit VARCHAR(16) COMMENT '单位',
  unit_price DECIMAL(10,2) COMMENT '单价',
  total_amount DECIMAL(10,2) COMMENT '总金额',
  used_quantity DECIMAL(10,2) DEFAULT 0 COMMENT '已使用数量',
  remaining_quantity DECIMAL(10,2) COMMENT '剩余数量',
  status VARCHAR(16) DEFAULT 'sufficient' COMMENT '状态: sufficient/low/depleted',
  greenhouse_id INT COMMENT '默认存放大棚',
  remark TEXT COMMENT '备注',
  create_by VARCHAR(32) COMMENT '创建人',
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  org_id INT COMMENT '组织ID',
  INDEX idx_code (code),
  INDEX idx_crop (crop_name, crop_variety),
  INDEX idx_supplier (supplier_id),
  INDEX idx_date (purchase_date)
) COMMENT='种源管理表';
```

#### 育苗表 tb_seedling

```sql
CREATE TABLE tb_seedling (
```

```typescript
  message: 'success';
  data: {
    total: number;
    page: number;
    pageSize: number;

  timestamp: string;
}
```

### 10.4 生长阶段定义

```typescript
enum GrowthStage {
  SEEDLING = 'seedling',     // 育苗期
  FLOWERING = 'flowering',    // 开花期
  FRUITING = 'fruiting',     // 结果期
  MATURE = 'mature'          // 成熟期
}

// 阶段进度计算
const getGrowthProgress = (stage: GrowthStage, growthDays: number) => {
  const stageProgress = {
    [GrowthStage.SEEDLING]: 25,
    [GrowthStage.FLOWERING]: 50,
    [GrowthStage.FRUITING]: 75,
    [GrowthStage.MATURE]: 100
  };
  return stageProgress[stage];
};
```
