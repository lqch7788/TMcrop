## 一、核心概念与数据模型

### 1.1 三大核心实体

| 实体 | 说明 | 存储位置 |
|------|------|----------|
| **Problem（问题）** | 业务中发现的问题记录 | `usePersistentProblems` hook |
| **Task（任务）** | 由问题分派产生的处理任务 | `useLocalStorage` STORAGE_KEYS.TASKS |
| **FlowRecord（流转记录）** | 状态变化的审计日志 | 内嵌于 Problem.flowRecords |

### 1.2 ProblemEntry 数据结构

```typescript
interface ProblemEntry {
  // 基础信息
  id: number;                    // 唯一标识，自增
  problemCode: string;           // 编号格式：PD + YYYYMMDD + 序号(3位)，如 PD20260415001

  // 来源追溯（关键！）
  sourceModule: 'inspection' | 'manual' | 'production' | 'equipment' | 'other';
  sourceId?: string;             // 原始单据ID（如巡查记录ID XT20260314-001）
  sourceDetail?: string;         // 来源详情

  // 巡查/生产等业务字段
  greenhouseId: string;
  greenhouseName: string;
  cropName: string;
  inspectorId: string;           // 上报人ID
  inspectorName: string;         // 上报人姓名
  checkDate: string;             // 格式：YYYY-MM-DD
  checkTime: string;

  // 问题描述
  issueText: string;            // 问题文本描述
  issueSeverity: '轻微' | '中等' | '严重';

  // 状态流转（核心！）
  status: '待处理' | '处理中' | '待验收' | '已处理';

  // 处理信息
  handler?: string;              // 当前执行人姓名（分派后设置）
  handleDate?: string;          // 处理完成日期
  handleResult?: string;        // 处理结果

  // 任务关联（关键！双向关联）
  sourceTaskId?: string;        // 关联的任务ID（Task.sourceProblemId 指向此 Problem）

  // 返工管控
  reworkCount?: number;          // 返工次数，默认0

  // 接单/拒单信息
  acceptedBy?: string;          // 接单人
  acceptedTime?: string;        // 接单时间
  rejectedBy?: string;         // 拒绝人
  rejectedReason?: string;     // 拒绝原因
  rejectedTime?: string;       // 拒绝时间

  // 完成信息
  completionTime?: string;       // 验收通过时间

  // 流转记录（数据闭环关键，不可缺失！）
  flowRecords?: ProblemFlowRecord[];
}
```

### 1.3 ProblemFlowRecord 数据结构

```typescript
interface ProblemFlowRecord {
  id: string;                   // 格式：FR-时间戳
  problemId: number;            // 关联的问题ID
  operatorId: string;           // 操作人ID（当前登录人）
  operatorName: string;         // 操作人姓名
  action: 'report' | 'dispatch' | 'accept' | 'reject' | 'start'
        | 'submit' | 'approve' | 'reject_acceptance' | 'complete' | 'comment' | 'progress';
  fromStatus: string;          // 操作前状态
  toStatus: string;            // 操作后状态
  comment?: string;            // 备注/原因
  actionTime: string;           // ISO时间
  progress?: number;            // 进度百分比（仅 progress 动作）
}
```

### 1.4 Task 数据结构

```typescript
interface Task {
  id: string;                   // 格式：RW-YYYYMMDD-序号，如 RW-20260415-001
  taskCode: string;             // 格式：TKRW-YYYYMMDD-序号，如 TKRW-20260415-001
  title: string;

  // 任务类型（影响图标和颜色）
  type: 'spraying' | 'irrigation' | 'fertilization' | 'scouting' | 'other';
  typeName: string;            // 中文名称

  // 优先级
  priority: 'urgent' | 'high' | 'medium' | 'low' | 'normal';

  // 状态机
  status: 'pending' | 'accepted' | 'in_progress' | 'waiting_acceptance' | 'completed' | 'rejected';

  // 批次信息
  batchId: string;
  batchCode: string;

  // 执行人
  assigneeId: string;
  assigneeName: string;
  assignerId: string;          // 分派人ID
  assignerName: string;        // 分派人姓名

  // 截止日期
  dueDate: string;

  // 工作量
  workDuration: number;
  actualWorkload: number;

  // 问题关联（关键！双向关联）
  sourceProblemId?: number;     // 关联的问题ID（Problem.sourceTaskId 指向此 Task）

  // 描述
  description: string;

  // 进度
  progress?: number;           // 0-100

  // 物料
  requiredMaterials: Array<{ name: string; quantity: number; unit: string }>;
}
```

## 二、问题处理完整状态机

### 2.1 状态流转图

```
                                    ┌─────────────────────────┐
                                    │      问题上报 → 待处理   │
                                    │   (report)             │
                                    └───────────┬─────────────┘
                                                │
                                          分派 dispatch
                                                │
                                                ▼
┌───────────────────────────────────────────────────────────────────────┐
│                                                                        │
│   ┌──────────┐     提交反馈      ┌──────────┐                         │
│   │ 处理中   │ ──── submit ───→  │ 待验收   │                         │
│   │(in_progress)                │(waiting) │                         │
│   └──────────┘                   └─────┬────┘                         │
│        ▲                               │                              │
│        │                               │ 验收 approve                │
│        │                               ▼                              │
│        │                         ┌──────────┐                         │
│        │                         │ 已处理   │                         │
│        │                         │(completed)                         │
│        │                         └──────────┘                         │
│        │                                                             │
│        │ rejectAcceptance (返工)                                     │
│        │                                                             │
│   ┌────┴────────────────────────────────────────────────────────┐     │
│   │                                                             │     │
│   │  reworkCount = 1: 保持原执行人，任务变为 in_progress        │     │
│   │  reworkCount >= 2: 退回待处理，重新分派                     │     │
│   │                                                             │     │
│   └─────────────────────────────────────────────────────────────┘     │
│                                                                        │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 任务状态与问题状态对应关系

| 问题状态 | 任务状态 | 说明 |
|---------|---------|------|
| 待处理（未分派） | - | 问题待分派给执行人 |
| 处理中 | pending → accepted → in_progress | 执行人接受并处理中 |
| 处理中（返工） | rejected → in_progress | 第一次返工保持原执行人 |
| 处理中（被拒绝） | rejected | 第二次返工退回分派页 |
| 待验收 | waiting_acceptance | 执行人提交完成，待验收 |
| 已处理 | completed | 验收通过，问题关闭 |

### 2.3 操作动作类型（action 字段）

| action | 触发时机 | 操作人 | fromStatus | toStatus |
|--------|---------|--------|-----------|---------|
| report | 问题上报 | 巡查员/上报人 | '' | '待处理' |
| dispatch | 问题分派 | 分派员 | '待处理' | '处理中' |
| accept | 接单 | 执行人 | '处理中' | '处理中' |
| reject | 拒绝任务 | 执行人 | '处理中' | '待处理' |
| progress | 提交进度 | 执行人 | '处理中' | '处理中' |
| submit | 提交验收 | 执行人 | '处理中' | '待验收' |
| approve | 验收通过 | 验收员 | '待验收' | '已处理' |
| reject_acceptance | 返工 | 验收员 | '待验收' | '处理中'或'待处理' |
| complete | 完成 | 系统 | '待验收' | '已处理' |

## 三、完整业务流程详解

### 3.1 阶段一：问题上报（Report）

**触发场景**：巡查员在巡查过程中发现问题时，勾选"需反馈"并选择反馈人员

**处理逻辑**（InspectionPage.tsx）：

```typescript
// 1. 合并问题描述
const issueText = presetIssues + (newRecord.issueText ? `\n${newRecord.issueText}` : '');

// 2. 严重程度自动推导
let severity = newRecord.issueSeverity || '中等';
if (!newRecord.issueSeverity && allIssueText.includes('灰霉')) {
  severity = '严重';  // 特殊规则：灰霉病自动升级为严重
}

// 3. 添加问题记录
newProblemId = addProblem({
  greenhouseId,
  greenhouseName,
  cropName,
  inspectorId: currentUserId,    // 【重要】使用当前登录人ID
  inspectorName: currentUserName,
  checkDate,
  checkTime,
  issueText,
  issueSeverity: severity,
  status: '待处理',
  sourceModule: 'inspection',     // 【重要】来源模块
  sourceId: newRecord.recordCode, // 关联巡查记录ID
});

// 4. 记录流转
flowRecord: {
  action: 'report',
  fromStatus: '',
  toStatus: '待处理',
  comment: '问题上报',
}
```

**问题编号生成规则**：
- 格式：`PD` + `YYYYMMDD` + 序号(3位)
- 例如：`PD20260415001`
- 同一天的问题序号递增

**存储**：
- 问题存入 `usePersistentProblems` hook
- 初始状态：`status: '待处理'`，`sourceTaskId: undefined`

### 3.2 阶段二：问题分派（Dispatch）

**触发场景**：问题分派员在"问题分派"页面选择待分派问题，选择执行人，点击分派

**处理逻辑**（useProblemDispatch.ts: dispatchProblem）：

```typescript
// 1. 创建任务
const newTask: Task = {
  id: generateTaskId(tasks),        // 格式：RW-YYYYMMDD-序号
  taskCode: generateTaskCode(tasks), // 格式：TKRW-YYYYMMDD-序号
  title: `【问题处理】${problem.issueText.slice(0, 30)}`,
  type: getProblemType(issueText),   // 根据问题文本自动判断
  priority: SEVERITY_PRIORITY_MAP[severity],
  status: 'pending',
  assigneeId,
  assigneeName,
  assignerId: dispatcherId,
  assignerName: dispatcherName,
  dueDate: calculateDueDate(severity),  // 严重=1天，中等=3天，轻微=7天
  sourceProblemId: problemId,        // 【关键】双向关联
  description: `问题描述：${issueText}\n严重程度：${severity}...`,
};

// 2. 保存任务
setTasks(prev => [...prev, newTask]);

// 3. 更新问题状态
updateProblem(problemId, {
  status: '处理中',
  handler: assigneeName,            // 【重要】记录执行人
  sourceTaskId: newTask.id,         // 【关键】双向关联
});

// 4. 记录流转
flowRecord: {
  action: 'dispatch',
  fromStatus: '待处理',
  toStatus: '处理中',
  comment: `分派给 ${assigneeName} 处理`,
}
```

**任务ID生成规则**：
- 格式：`RW-YYYYMMDD-序号`，如 `RW-20260415-001`
- 格式：`TKRW-YYYYMMDD-序号`，如 `TKRW-20260415-001`
- 同一天的任务序号递增

**截止日期计算**：
| 严重程度 | 截止日期 |
|---------|---------|
| 严重 | 当天 + 1天 |
| 中等 | 当天 + 3天 |
| 轻微 | 当天 + 7天 |

**问题类型→任务类型自动映射**：
| 问题文本关键词 | 任务类型 |
|--------------|---------|
| 虫、蚜 | spraying（打药） |
| 病、斑、灰霉 | spraying（打药） |
| 水、旱 | irrigation（灌溉） |
| 肥 | fertilization（施肥） |
| 其他 | scouting（巡查） |

### 3.4 阶段四：提交验收（Submit）

**触发场景**：执行人完成任务处理，填写处理结果，提交待验收

**处理逻辑**（MyTasksPage.tsx: handleSubmitFeedback）：

```typescript
// 1. 记录问题流转
addProgressRecord(task.sourceProblemId, currentUserId, currentUserName, task.progress, feedbackForm.resultText);

// 2. 进度100%时触发问题状态更新
if (task.progress === 100) {
  submitProblemFeedback(task.sourceProblemId, currentUserId, currentUserName, {
    resultText: feedbackForm.resultText,
    actualWorkload: feedbackForm.actualWorkload,
  });
}

// 3. 更新任务状态
const newStatus = task.progress === 100 ? 'waiting_acceptance' : 'in_progress';
setTasks(prev => prev.map(t =>
  t.id === task.id ? { ...t, status: newStatus, progress: task.progress } : t
));
```

**submitProblemFeedback 内部逻辑**：

### 3.5 阶段五：验收与返工（Acceptance & Rework）

**触发场景**：验收员在巡查列表或问题分派页面点击"验收"，通过或返工

#### 3.5.1 验收通过

```typescript
// 1. 更新问题状态
updateProblem(problemId, {
  status: '已处理',
  completionTime: getCurrentTime(),
});

// 2. 同步更新任务状态
if (problem.sourceTaskId) {
  setTasks(prev => prev.map(t =>
    t.id === problem.sourceTaskId
      ? { ...t, status: 'completed', progress: 100 }
      : t
  ));
}

// 3. 流转记录
flowRecord: {
  action: 'approve',
  fromStatus: '待验收',
  toStatus: '已处理',
  comment: '验收通过，问题关闭',
}
```

#### 3.5.2 返工（核心：分次数管控）

**规则**：
- **第一次返工**（reworkCount: 0→1）：保持原执行人，执行人在"我的任务"继续处理
- **第二次返工**（reworkCount: 1→2）：退回问题分派页面，由分派员重新分派

```typescript
const rejectAcceptance = (problemId, operatorId, operatorName, reason) => {
  const newReworkCount = (problem.reworkCount || 0) + 1;
  const shouldReassign = newReworkCount >= 2;

  const flowRecord: ProblemFlowRecord = {
    id: `FR-${Date.now()}`,
    problemId,
    operatorId,
    operatorName,
    action: 'reject_acceptance',
    fromStatus: problem.status,
    toStatus: shouldReassign ? '待处理' : problem.status,
    comment: `返工原因：${reason}${shouldReassign ? '【已超限，退回重新分派】' : ''}`,
    actionTime: new Date().toISOString(),
  };

  if (shouldReassign) {
    // 【第二次返工】清除执行人，问题退回待分派
    updateProblem(problemId, {
      status: '待处理',
      handler: undefined,
      sourceTaskId: undefined,  // 清除关联，问题重新进入待分派列表
      reworkCount: newReworkCount,
      flowRecords: [...(problem.flowRecords || []), flowRecord],
    });
    // 关联任务变为已拒绝
    setTasks(prev => prev.map(t =>
      t.id === problem.sourceTaskId ? { ...t, status: 'rejected' } : t
    ));
  } else {
    // 【第一次返工】保持原执行人，增加返工计数
    updateProblem(problemId, {
      reworkCount: newReworkCount,
      flowRecords: [...(problem.flowRecords || []), flowRecord],
    });
    // 关联任务变为进行中，执行人继续处理
    setTasks(prev => prev.map(t =>
      t.id === problem.sourceTaskId ? { ...t, status: 'in_progress' } : t
    ));
  }
};
```

**返工状态对应表**：

| reworkCount | 问题状态 | 任务状态 | 执行人 | 出现位置 |
|------------|---------|---------|--------|---------|
| 0 | 待处理 | - | - | 问题分派页 |
| 0 | 处理中 | pending/accepted/in_progress | 已分派 | 我的任务 |
| 1 | 处理中 | in_progress | 原执行人 | 我的任务 |
| 2 | 待处理 | rejected | - | 问题分派页（重新分派） |

  problemId,        // 问题ID

  dispatcherId,    // 分派人ID（当前登录人）

console.assert(task.sourceProblemId === problemId, '任务-问题关联错误');

## 六、与其他业务模块的整合模式

### 6.1 通用问题处理模式

所有业务模块（生产/采购/设备等）的问题处理都遵循以下模式：

```
业务模块 → 创建问题 → 问题分派 → 任务执行 → 提交验收 → 验收通过/返工
```

### 6.2 sourceModule 可选值

| sourceModule | 来源模块 | 示例 |
|-------------|---------|------|
| inspection | 巡查管理 | 巡查发现的问题 |
| production | 生产管理 | 生产过程中的问题 |
| equipment | 设备管理 | 设备故障问题 |
| manual | 手动录入 | 人工上报的问题 |
| other | 其他 | 其他来源 |

### 6.3 整合检查清单

新增业务模块时，必须确认：

- [ ] 问题有 `sourceModule` 标识来源
- [ ] 问题有 `sourceId` 关联原始单据
- [ ] 问题状态流转遵循标准状态机
- [ ] 所有状态变化都有 `flowRecords` 记录
- [ ] 问题和任务保持双向关联
- [ ] 返工逻辑遵循 reworkCount 规则

## 七、错误教训与注意事项

### 7.1 五大常见错误

#### 错误1：硬编码用户ID

**错误**：
```typescript
// ❌ 错误：写死用户ID
acceptProblem(task.sourceProblemId, 'U013', '陆启闯');
```

**正确**：
```typescript
// ✅ 正确：从当前会话获取用户
const currentUser = getCurrentUser();
acceptProblem(task.sourceProblemId, currentUser.id, currentUser.name);
```

#### 错误2：缺少流转记录

**错误**：
```typescript
// ❌ 错误：直接更新状态，没有记录流转
updateProblem(problemId, { status: '处理中' });
```

**正确**：
```typescript
// ✅ 正确：更新状态时同时记录流转
updateProblem(problemId, {
  status: '处理中',
  flowRecords: [...(problem.flowRecords || []), flowRecord],
});
```

#### 错误3：双向关联不一致

**错误**：
```typescript
// ❌ 错误：只设置一边
task.sourceProblemId = problemId;
// 但没有设置 problem.sourceTaskId = task.id
```

**正确**：
```typescript
// ✅ 正确：同时设置双向关联
// 创建任务时
task.sourceProblemId = problemId;
updateProblem(problemId, { sourceTaskId: task.id });

// 查询时
const task = tasks.find(t => t.sourceProblemId === problemId);
const problem = problems.find(p => p.sourceTaskId === taskId);
```

#### 错误4：状态更新不完整

**错误**：
```typescript
// ❌ 错误：只更新问题状态，不更新任务状态
updateProblem(problemId, { status: '已处理' });
// 任务状态仍是 'waiting_acceptance'
```

**正确**：
```typescript
// ✅ 正确：同时更新问题和任务状态
updateProblem(problemId, { status: '已处理' });
if (problem.sourceTaskId) {
  setTasks(prev => prev.map(t =>
    t.id === problem.sourceTaskId
      ? { ...t, status: 'completed' }
      : t
  ));
}
```

#### 错误5：编号生成冲突

**错误**：
```typescript
// ❌ 错误：页面刷新后序号重置
dailyProblemCount[dateKey] = 1;  // 刷新后从1开始
```

**正确**：
```typescript
// ✅ 正确：初始化时从 localStorage 读取最大序号
const stored = localStorage.getItem(STORAGE_KEYS.DAILY_PROBLEMS);
if (stored) {
  const problems = JSON.parse(stored);
  problems.forEach(p => {
    const dateKey = p.checkDate.replace(/-/g, '');
    const seq = parseInt(p.problemCode.slice(-3));
    dailyProblemCount[dateKey] = Math.max(dailyProblemCount[dateKey] || 0, seq);
  });
}
```

## 八、验证步骤

### 8.1 完整流程验证

1. **问题上报**
   - 打开巡查管理页面
   - 创建带问题的巡查记录
   - 确认问题出现在"问题分派"页面的待分派列表

2. **问题分派**
   - 在问题分派页面选择问题
   - 选择执行人，点击分派
   - 确认问题状态变为"处理中"
   - 确认"我的任务"出现新任务

3. **任务执行**
   - 在"我的任务"页面接受任务
   - 提交进度（50%）
   - 继续处理，提交进度（100%）
   - 填写处理结果，提交验收

4. **验收流程**
   - 在巡查列表找到问题，点击"验收"
   - 选择"验收通过"或"返工"
   - 验收通过：确认问题状态变为"已处理"
   - 返工：确认 reworkCount 增加，第一次返工保持原执行人

### 8.2 状态一致性验证

在控制台执行：

```javascript
// 验证所有已处理问题的任务都已完成
const problems = JSON.parse(localStorage.getItem('daily_problems'));
const tasks = JSON.parse(localStorage.getItem('daily_tasks'));

problems.filter(p => p.status === '已处理').forEach(p => {
  if (p.sourceTaskId) {
    const task = tasks.find(t => t.id === p.sourceTaskId);
    console.assert(task.status === 'completed',
      `问题 ${p.problemCode} 关联任务 ${task?.id} 状态异常: ${task?.status}`);
  }
});
```
