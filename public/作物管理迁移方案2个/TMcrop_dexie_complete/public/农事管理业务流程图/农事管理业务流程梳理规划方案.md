# 农事管理系统业务流程梳理规划方案

## 一、项目背景与目标

### 1.1 项目背景
农事管理系统是一个涵盖任务新建、分派、提交、验收等完整业务流程的综合管理系统。需要对系统中所有涉及这些流程的页面和模块进行系统性的梳理，明确各流程之间的关联关系。

### 1.2 梳理目标
1. 识别农事管理所有业务流程
2. 分析流程间的数据关联
3. 确定需要绘制的业务流程图清单
4. 输出完整的业务流程文档

### 3.2 详细业务流程分解

#### 流程一：任务新建与派发流程

**涉及页面/组件：**
- `src/components/farm/hub/CreateTaskModal.tsx`
- `src/components/farm/hub/TaskTab.tsx`
- `src/hooks/useTasks.ts`

**流程步骤：**

| 步骤 | 操作 | 参与者 | 数据输入 | 状态变化 |
|------|------|--------|----------|----------|
| 1 | 点击"新建任务" | 管理员 | 任务标题、类型、执行区域、计划日期、预计工时、优先级、执行人 | - |
| 2 | 填写任务信息 | 管理员 | 完整任务数据 | - |
| 3 | 数据校验 | 系统 | title.trim()!=='', greenhouse.trim()!=='' | - |
| 4 | 创建任务 | 系统 | 任务对象 | 状态=pending(有执行人) 或 draft(无执行人) |
| 5 | 选择执行人 | 管理员 | 选中任务+执行人 | - |
| 6 | 批量派发 | 系统 | 任务ID列表、执行人ID | draft/rejected → pending |

**关联数据：**
- `Task` 任务表
- `TaskRecord` 操作记录表
- `FarmBatch` 生产批次表

#### 流程二：任务接受与执行流程

**涉及页面/组件：**
- `src/components/labor/myTasks/MyTasksPage.tsx`
- `src/components/farm/hub/TaskDetailModal.tsx`
- `src/hooks/useTasks.ts`

**流程步骤：**

| 步骤 | 操作 | 参与者 | 数据输入 | 状态变化 |
|------|------|--------|----------|----------|
| 1 | 查看待接受任务 | 执行人 | - | - |
| 2 | 点击"接受任务" | 执行人 | taskId | pending → accepted |
| 3 | 创建考勤记录 | 系统 | 执行人ID、日期时间 | Attendance表新增 |
| 4 | 点击"开始处理" | 执行人 | taskId | accepted → in_progress |
| 5 | 填写进度反馈 | 执行人 | 进度%、处理结果、GPS、照片 | - |
| 6 | 提交进度 | 系统 | 反馈数据 | 进度<100%保持in_progress |

**关联数据：**
- `Task` 任务表
- `TaskRecord` 操作记录表
- `Attendance` 考勤记录表

#### 流程三：任务验收与完成流程

**涉及页面/组件：**
- `src/components/farm/hub/VerifyTaskModal.tsx`
- `src/components/farm/hub/TaskTab.tsx`
- `src/hooks/useTasks.ts`

**流程步骤：**

| 步骤 | 操作 | 参与者 | 数据输入 | 状态变化 |
|------|------|--------|----------|----------|
| 1 | 执行人提交100%进度 | 执行人 | 最终反馈数据 | in_progress → waiting_acceptance |
| 2 | 派发人/管理员查看待验收 | 派发人/管理员 | - | - |
| 3 | 点击"验收"打开验收弹窗 | 派发人/管理员 | taskId | - |
| 4 | 选择验收结果 | 派发人/管理员 | 通过/驳回 | - |
| 5 | 验收通过 | 系统 | - | waiting_acceptance → completed |
| 6 | 验收驳回(第1次) | 系统 | 驳回原因 | waiting_acceptance → rejected |
| 7 | 验收驳回(第2次) | 系统 | 驳回原因 | rejected → failed |

**关联数据：**
- `Task` 任务表
- `TaskRecord` 操作记录表
- `WorkLog` 工作日志表（自动同步）

### 4.2 状态流转关系

**任务状态流转：**
```
draft ──派发──▶ pending ──接受──▶ accepted ──开始──▶ in_progress
                                                           │
                                              ┌────────────┴────────────┐
                                              │                         │
                                         提交100%                   取消
                                              │                         │
                                              ▼                         ▼
                                   waiting_acceptance ◀──────── cancelled
                                          │
                            ┌─────────────┴─────────────┐
                            │                           │
                       验收通过                      验收驳回
                            │                           │
                            ▼                           ▼
                      completed                    rejected
                                                (返工中)
                                                     │
                                                第2次驳回
                                                     │
                                                     ▼
                                                  failed
                                              (任务失败)
```

**问题状态流转：**
```
待处理 ──分派──▶ 处理中 ──提交──▶ 待验收 ──验收通过──▶ 已处理
                         │
                         └──────── 驳回重处理 ────────┘
```

## 十、备注

### 10.1 数据流转一致性说明

| 同步场景 | 触发时机 | 同步内容 |
|----------|----------|----------|
| 任务完成 → 工作日志 | 任务状态变为completed | 自动创建WorkLogEntry |
| 任务接受 → 考勤记录 | 任务状态变为accepted | 自动创建Attendance |
| 巡查发现 → 问题记录 | 巡查员点击"导入问题" | 创建ProblemEntry |
| 问题分派 → 关联任务 | 问题分派时勾选"同时创建任务" | 创建Task |
