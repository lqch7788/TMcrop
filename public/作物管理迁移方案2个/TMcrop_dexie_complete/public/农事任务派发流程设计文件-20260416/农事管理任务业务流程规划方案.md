## 二、业务流程全景图

### 2.1 任务生命周期状态流转

```
[草稿] (draft)
   ↓
[待接受] (pending) ← 创建任务时指定执行人，或直接派发
   ↓               ← 草稿状态任务被分派
   ↓               ← 返工任务被重新派发
[已接受] (accepted)
   ↓
[进行中] (in_progress)
   ↓
[待验收] (waiting_acceptance)
   ↓ ↗ [驳回] → [进行中] (in_progress) ← 验收不通过，需返工
   ↓
[已完成] (completed) ← 验收通过
```

**异常状态：**
- [返工中] (rejected)：验收驳回后的中间状态，需重新派发

### 2.2 业务流程清单

根据代码分析，共识别出以下 **13 个核心业务流程**：

| 流程编号 | 流程名称 | 所属模块 | 触发入口 |
|---------|---------|---------|---------|
| F01 | 任务创建流程 | 任务管理 | CreateTaskModal / 从问题创建 / 从巡查创建 |
| F02 | 任务分派流程 | 任务管理 | TaskTab批量派发 / CreateTaskModal直接派发 |
| F03 | 任务接受流程 | 任务管理 | TaskDetailModal / TaskDispatchPage |
| F04 | 任务执行流程 | 任务管理 | TaskDispatchPage |
| F05 | 任务提交流程 | 任务管理 | TaskDispatchPage |
| F06 | 任务验收流程 | 任务管理 | VerifyTaskModal / TaskTab批量验收 |
| F07 | 任务返工流程 | 任务管理 | VerifyTaskModal驳回 / 批量验收驳回 |
| F08 | 问题分派流程 | 问题管理 | ProblemTab / ProblemDispatchModal |
| F09 | 问题处理流程 | 问题管理 | ProblemTab |
| F10 | 巡查创建流程 | 巡查记录 | 新建巡查按钮 |
| F11 | 巡查问题上报流程 | 巡查记录 | InspectionDetailModal |

## 三、详细业务流程图与关联数据

### 流程 F01：任务创建流程

**流程描述：** 用户通过新建任务弹窗创建农事任务，可选择直接分派或保存为草稿。

**流程图：**

```
[开始]
  ↓
[用户点击"新建任务"]
  ↓
[打开 CreateTaskModal]
  ↓
[填写任务基本信息]
  ├── 任务标题（必填）
  ├── 任务类型（灌溉/施肥/打药/除草等）
  ├── 关联批次（可选）
  ├── 执行区域（必填）
  ├── 计划日期
  ├── 预计工时
  ├── 优先级（紧急/高/中/低）
  ├── 任务描述
  └── 选择执行人（可选）
  ↓
[判断是否选择执行人]
  ├── 是 → 状态 = pending（待接受），生成操作记录"分派任务"
  └── 否 → 状态 = draft（草稿）
  ↓
[生成任务编号 TK{日期}{随机码}]
  ↓
[保存到 localStorage: farm_tasks]
  ↓
[记录操作日志到 localStorage: farm_tasks_records]
  ├── 操作类型: create/assign
  ├── 操作时间
  ├── 操作人
  ├── 任务编号
  └── 任务标题
  ↓
[关闭弹窗，刷新页面数据]
  ↓
[结束]
```

**关联数据表：**

| 数据字段 | 类型 | 必填 | 说明 |
|---------|------|------|------|
| id | string | 是 | 任务唯一标识 `task-{timestamp}` |
| taskCode | string | 是 | 任务编号 `TK{YYYYMMDD}{随机码}` |
| title | string | 是 | 任务标题 |
| description | string | 否 | 任务详细描述 |
| type | string | 是 | 任务类型值 |
| typeName | string | 是 | 任务类型显示名 |
| batchCode | string | 否 | 关联批次编号 |
| greenhouseName | string | 是 | 执行区域/大棚名称 |
| plannedDate | string | 否 | 计划日期 |
| estimatedHours | number | 否 | 预计工时（小时） |
| dueDate | string | 否 | 截止日期 |
| priority | enum | 是 | 优先级：urgent/high/medium/low |
| status | enum | 是 | draft 或 pending |
| progress | number | 是 | 进度（初始为0） |
| assigneeId | string | 否 | 执行人ID |
| assigneeName | string | 否 | 执行人姓名 |
| createdAt | string | 是 | 创建时间 ISO格式 |
| updatedAt | string | 是 | 更新时间 ISO格式 |
| sourceType | string | 否 | 来源类型：problem/inspection |
| sourceId | string | 否 | 来源ID |
| dispatchMode | string | 是 | 派发模式：farm（固定值） |

### 流程 F02：任务分派流程

**流程描述：** 将草稿或返工状态的任务分派给执行人。

**流程图：**

```
[开始]
  ↓
[用户选择任务] ← 来源：TaskTab列表 / 批量派发模式
  ↓
[判断分派方式]
  ├── 单个任务分派 → TaskDetailModal / TaskDispatchPage
  └── 批量分派 → TaskTab批量派发弹窗
  ↓
[选择执行人]
  ├── 从工人列表选择（长期工/临时工）
  └── 显示工人信息（姓名/工种/工作区域）
  ↓
[确认分派]
  ↓
[更新任务状态：draft/rejected → pending]
  ↓
[更新任务字段]
  ├── assigneeId = 选中的执行人ID
  ├── assigneeName = 选中的执行人姓名
  ├── dispatchedAt = 当前时间
  └── updatedAt = 当前时间
  ↓
[保存到 localStorage: farm_tasks]
  ↓
[记录操作日志]
  ├── action: assign
  ├── 操作人
  ├── 任务编号
  └── 任务标题
  ↓
[刷新页面数据]
  ↓
[结束]
```

**关联数据变更：**

| 操作 | 变更前 | 变更后 |
|------|--------|--------|
| 状态 | draft / rejected | pending（待接受） |
| assigneeId | 空/旧值 | 新执行人ID |
| assigneeName | 空/旧值 | 新执行人姓名 |
| dispatchedAt | 空/旧值 | 当前时间 |
| updatedAt | 旧值 | 当前时间 |

**可批量分派的任务状态：**
- draft（草稿）
- rejected（返工中）

### 流程 F06：任务验收流程

**流程描述：** 验收人员对已提交的任务进行验收，判断是否通过。

**流程图：**

```
[开始]
  ↓
[验收人员查看待验收任务列表]
  ↓
[点击"验收"按钮]
  ↓
[打开 VerifyTaskModal]
  ↓
[查看任务执行详情]
  ├── 任务基本信息
  ├── 执行人信息
  ├── 完成报告
  ├── 现场照片
  └── 实际工时
  ↓
[判断验收结果]
  ↓
[分支1: 验收通过]
  ├── 填写验收意见（可选）
  ├── 更新状态：waiting_acceptance → completed
  ├── 记录 completedAt = 当前时间
  ├── 记录 verifyResult = pass
  ├── 记录 verifyFeedback = 验收意见
  └── 记录操作日志 action: verify
  ↓
[分支2: 验收驳回]
  ├── 填写驳回原因（必填）
  ├── 更新状态：waiting_acceptance → in_progress（返工）
  ├── 增加 reworkCount = reworkCount + 1
  ├── 记录 verifyResult = reject
  ├── 记录 verifyFeedback = 驳回原因
  └── 记录操作日志 action: reject
  ↓
[保存到 localStorage: farm_tasks]
  ↓
[关闭弹窗，刷新页面数据]
  ↓
[结束]
```

**关联数据变更（验收通过）：**

| 操作 | 变更前 | 变更后 |
|------|--------|--------|
| 状态 | waiting_acceptance（待验收） | completed（已完成） |
| completedAt | 空 | 当前时间 |
| verifyResult | 空 | pass |
| verifyFeedback | 空 | 验收意见 |
| updatedAt | 旧值 | 当前时间 |

**关联数据变更（验收驳回）：**

| 操作 | 变更前 | 变更后 |
|------|--------|--------|
| 状态 | waiting_acceptance（待验收） | in_progress（进行中）或 rejected |
| reworkCount | n | n+1 |
| verifyResult | 空 | reject |
| verifyFeedback | 空 | 驳回原因 |
| updatedAt | 旧值 | 当前时间 |

## 五、跨模块关联关系

### 5.1 模块间数据关联

```
[巡查记录] ──发现──→ [问题] ──分派──→ [处理]
                       │
                       └──基于──→ [任务创建] ──分派──→ [任务执行] ──提交──→ [任务验收]
```

### 5.2 跨模块触发关系

| 触发源 | 触发目标 | 触发条件 | 传递数据 |
|--------|---------|---------|---------|
| 问题管理 | 任务创建 | 从问题创建任务 | problemId, problemText, severity |
| 巡查记录 | 问题上报 | 巡查中发现问题 | inspectionId, location, photos |
| 巡查记录 | 任务创建 | 从巡查创建任务 | inspectionId, greenhouseName |
| 任务验收 | 问题管理 | 验收不通过产生问题 | taskId, rejectReason |

### 5.3 统一状态管理

所有模块通过 `useFarmHub` Hook 实现统一状态管理：

- **任务数据：** 从 `useTasks` 获取，过滤 `dispatchMode === 'farm'` 的任务
- **问题数据：** 从 `usePersistentProblems` 获取
- **巡查数据：** 从 `localStorage: inspection_records` 读取
- **操作记录：** 从 `farm_tasks_records` 和 `operation_records` 转换合并

## 六、关键数据结构汇总

### 6.1 Task 完整数据结构

```typescript
interface Task {
  // 基础信息
  id: string;                    // 任务唯一ID
  taskCode: string;              // 任务编号（自动生成）
  title: string;                 // 任务标题
  description: string;           // 任务描述
  type: string;                  // 任务类型值
  typeName: string;              // 任务类型显示名
  
  // 关联信息
  batchCode: string;             // 关联批次编号
  greenhouseName: string;        // 执行区域
  sourceType: 'problem' | 'inspection';  // 来源类型
  sourceId: string;              // 来源ID
  
  // 时间信息
  plannedDate: string;           // 计划日期
  dueDate: string;               // 截止日期
  estimatedHours: number;        // 预计工时
  createdAt: string;             // 创建时间
  updatedAt: string;             // 更新时间
  dispatchedAt: string;          // 分派时间
  startedAt: string;             // 开始时间
  submittedAt: string;           // 提交时间
  completedAt: string;           // 完成时间
  
  // 人员信息
  assigneeId: string;            // 执行人ID
  assigneeName: string;          // 执行人姓名
  
  // 状态信息
  status: TaskStatus;            // 任务状态
  progress: number;              // 进度（0-100）
  priority: 'urgent' | 'high' | 'medium' | 'low';  // 优先级
  dispatchMode: 'farm';          // 派发模式
  
  // 验收信息
  verifyResult: 'pass' | 'reject';  // 验收结果
  verifyFeedback: string;        // 验收意见/驳回原因
  completionNote: string;        // 完成说明
  reworkCount: number;           // 返工次数
  reworkReason: string;          // 返工原因
}

type TaskStatus = 
  | 'draft'              // 草稿
  | 'pending'            // 待接受
  | 'accepted'           // 已接受
  | 'in_progress'        // 进行中
  | 'waiting_acceptance' // 待验收
  | 'completed'          // 已完成
  | 'rejected';          // 返工中
```
