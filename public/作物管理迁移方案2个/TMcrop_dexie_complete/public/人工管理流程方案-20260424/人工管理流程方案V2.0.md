```typescript
interface Approval {
  id: string;
  code: string;                      // 审批单号
```

## 四、详细审批流程设计

### 4.1 入职审批流程

**业务场景：** 新员工入职需要经过审批流程，审批通过后自动创建员工记录并开通相关权限。

**流程图：**

```
[招聘录用]
  ↓
[发起入职审批]
  ↓
[填写入职审批单]
  ├── 员工基本信息（姓名、身份证、联系方式）
  ├── 岗位信息（部门、岗位、班组）
  ├── 薪酬信息（月薪、试用期工资）
  ├── 入职日期
  ├── 合同信息（合同类型、合同期限）
  └── 附件（身份证复印件、学历证明、体检报告）
  ↓
[提交审批] → 状态: DRAFT → PENDING
  ↓
[审批流程]
  ├── 一级审批：部门主管
  ├── 二级审批：HR经理
  └── 三级审批：总经理（可选）
  ↓
[审批结果]
  ├── 通过 → APPROVED → 触发业务联动
  ├── 拒绝 → REJECTED → 通知申请人
  └── 部分通过 → PARTIALLY_APPROVED → 修改后重新提交
  ↓
[审批通过 - 业务联动触发]
  ├── 1. 创建员工记录 → yuanxingtu_employees
  │   ├── 生成员工ID和编号
  │   ├── 设置状态为"试用期"
  │   └── 记录入职日期
  ├── 2. 创建考勤账号 → yuanxingtu_attendance
  │   └── 员工可打卡
  ├── 3. 创建薪酬记录 → yuanxingtu_salaries
  │   └── 设置薪酬标准
  ├── 4. 创建合同记录 → yuanxingtu_contracts
  │   └── 记录合同信息
  └── 5. 通知相关人员
      ├── 通知员工入职
      ├── 通知班组主管
      └── 通知考勤管理员
  ↓
[入职完成]
```

**业务联动接口：**

```typescript
interface OnboardingApprovalData {
  // 审批单基础信息
  approvalId: string;
  applicantId: string;
  applicantName: string;
  
  // 员工信息
  employeeInfo: {
    name: string;
    idCard: string;
    phone: string;
    gender: 'male' | 'female';
    birthDate: string;
    address: string;
    bankAccount: string;
    bankName: string;
    emergencyContact: string;
    emergencyPhone: string;
  };
  
  // 岗位信息
  positionInfo: {
    department: string;
    position: string;
    teamId: string;
    teamName: string;
    employeeType: 'regular' | 'temp';
  };
  
  // 薪酬信息
  salaryInfo: {
    monthlySalary: number;
    probationSalary: number;
    probationMonths: number;
    payDate: number; // 发薪日
  };
  
  // 合同信息
  contractInfo: {
    contractType: 'fixed' | 'open' | 'project';
    startDate: string;
    endDate: string;
    probationEndDate: string;
  };
  
  // 附件
  attachments: string[];
}

// 审批通过后的联动函数
async function handleOnboardingApproved(approval: OnboardingApprovalData): Promise<void> {
  // 1. 创建员工记录
  const employee = createEmployee(approval);
  
  // 2. 创建考勤账号
  createAttendanceAccount(employee.id);
  
  // 3. 创建薪酬记录
  createSalaryRecord(employee.id, approval.salaryInfo);
  
  // 4. 创建合同记录
  createContract(employee.id, approval.contractInfo);
  
  // 5. 通知相关人员
  notifyStakeholders(employee, approval);
}
```

### 4.3 请假审批流程（对接现有）

**业务场景：** 员工提交请假申请，审批通过后自动更新考勤记录。

**现状问题：** 请假审批与请假管理Tab完全独立。

**V2.0对接方案：**

```
[员工提交请假申请]
  ↓
[创建请假审批单] → yuanxingtu_approvals
  ├── 请假类型（年假/事假/病假/婚假/产假/丧假）
  ├── 请假时间（开始日期、结束日期、总天数）
  ├── 请假原因
  ├── 工作交接人
  └── 附件（病假条等）
  ↓
[审批流程]
  ├── 部门主管审批
  └── HR经理审批（长假需要）
  ↓
[审批通过 - 业务联动]
  ├── 1. 创建请假记录 → yuanxingtu_leaves
  │   ├── 关联审批单ID
  │   ├── 请假类型
  │   ├── 请假时间
  │   └── 状态: approved
  ├── 2. 更新考勤记录
  │   └── 对应日期的考勤状态改为"请假"
  ├── 3. 标记排班状态
  │   └── 对应日期的排班标记为"请假"
  └── 4. 通知相关人员
      ├── 通知工作交接人
      └── 通知考勤管理员
  ↓
[审批拒绝]
  └── 通知申请人，不创建请假记录
```

**对接关键点：**

```typescript
// 请假审批通过后的联动
async function handleLeaveApproved(approval: LeaveApprovalData): Promise<void> {
  // 1. 创建请假记录
  const leaveRecord = {
    id: generateId(),
    approvalId: approval.id,  // 关联审批单
    employeeId: approval.employeeId,
    leaveType: approval.leaveType,
    startDate: approval.startDate,
    endDate: approval.endDate,
    totalDays: approval.totalDays,
    reason: approval.reason,
    status: 'approved',
    createdAt: new Date().toISOString(),
  };
  saveToLocalStorage('yuanxingtu_leaves', leaveRecord);
  
  // 2. 更新考勤记录
  updateAttendanceForLeave(approval.employeeId, approval.startDate, approval.endDate);
  
  // 3. 更新排班状态
  updateScheduleForLeave(approval.employeeId, approval.startDate, approval.endDate);
}
```

```typescript
// 审批-业务联动引擎
class ApprovalBusinessBridge {
  // 审批通过处理映射
  private approvalHandlers = {
    [ApprovalType.ONBOARDING]: this.handleOnboardingApproved,
    [ApprovalType.REGULARIZATION]: this.handleRegularizationApproved,
    [ApprovalType.LEAVE]: this.handleLeaveApproved,
    [ApprovalType.OVERTIME]: this.handleOvertimeApproved,
    [ApprovalType.TRANSFER]: this.handleTransferApproved,
    [ApprovalType.RESIGN]: this.handleResignApproved,
    [ApprovalType.CONTRACT_SIGN]: this.handleContractSignApproved,
    [ApprovalType.CONTRACT_TERMINATE]: this.handleContractTerminateApproved,
    [ApprovalType.SALARY_ADJUST]: this.handleSalaryAdjustApproved,
    [ApprovalType.PIECEWORK_RATE]: this.handlePieceworkRateApproved,
    [ApprovalType.BUDGET_APPROVAL]: this.handleBudgetApproved,
    [ApprovalType.TEMP_HIRE]: this.handleTempHireApproved,
    [ApprovalType.SKILL_CERTIFICATION]: this.handleSkillCertificationApproved,
    [ApprovalType.ATTENDANCE_CORRECT]: this.handleAttendanceCorrectApproved,
  };

  // 监听审批状态变化
  watchApprovalStatus(): void {
    // 监听 localStorage 中审批单的变化
    // 当审批状态从 PENDING 变为 APPROVED 时触发联动
  }

  // 处理审批通过
  async handleApprovalApproved(approval: Approval): Promise<void> {
    const handler = this.approvalHandlers[approval.type];
    if (handler) {
      await handler.call(this, approval);
    }
  }

  // 入职审批处理
  private async handleOnboardingApproved(approval: Approval): Promise<void> {
    const data = approval.businessLink as OnboardingApprovalData;
    
    // 1. 创建员工记录
    const employee = {
      id: generateId(),
      employeeCode: this.generateEmployeeCode(),
      name: data.employeeInfo.name,
      idCard: data.employeeInfo.idCard,
      phone: data.employeeInfo.phone,
      gender: data.employeeInfo.gender,
      department: data.positionInfo.department,
      position: data.positionInfo.position,
      teamId: data.positionInfo.teamId,
      employeeType: data.positionInfo.employeeType,
      status: 'probation',
      entryDate: approval.applyDate,
      probationEndDate: data.contractInfo.probationEndDate,
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString(),
    };
    
    // 保存到员工数据中心
    saveEmployee(employee);
    
    // 2. 创建考勤账号
    createAttendanceAccount(employee.id);
    
    // 3. 创建薪酬记录
    createSalaryRecord(employee.id, {
      monthlySalary: data.salaryInfo.monthlySalary,
      probationSalary: data.salaryInfo.probationSalary,
      payDate: data.salaryInfo.payDate,
    });
    
    // 4. 创建合同记录
    createContract(employee.id, {
      contractType: data.contractInfo.contractType,
      startDate: data.contractInfo.startDate,
      endDate: data.contractInfo.endDate,
      probationEndDate: data.contractInfo.probationEndDate,
      salary: data.salaryInfo.monthlySalary,
    });
    
    // 5. 通知相关人员
    notifyOnboardingComplete(employee, data);
  }

  // 请假审批处理
  private async handleLeaveApproved(approval: Approval): Promise<void> {
    const data = approval.businessLink as LeaveApprovalData;
    
    // 1. 创建请假记录
    const leaveRecord = {
      id: generateId(),
      approvalId: approval.id,
      employeeId: data.employeeId,
      leaveType: data.leaveType,
      startDate: data.startDate,
      endDate: data.endDate,
      totalDays: data.totalDays,
      reason: data.reason,
      status: 'approved',
      createdAt: new Date().toISOString(),
    };
    saveLeave(leaveRecord);
    
    // 2. 更新考勤记录
    updateAttendanceForLeave(data.employeeId, data.startDate, data.endDate);
    
    // 3. 更新排班状态
    updateScheduleForLeave(data.employeeId, data.startDate, data.endDate);
  }

  // 其他审批类型的处理方法...
}
```

### 8.1 关联记录数据结构

```typescript
// 审批-业务关联记录
interface ApprovalBusinessLink {
  id: string;                    // 关联记录ID
  approvalId: string;            // 审批单ID
  approvalType: ApprovalType;    // 审批类型
  approvalCode: string;          // 审批单号
  approvalStatus: ApprovalStatus; // 审批状态
  
  // 关联的业务记录
  businessRecords: Array<{
    type: 'employee' | 'attendance' | 'leave' | 'overtime' | 
          'salary' | 'contract' | 'skill' | 'budget' | 'piecework';
    recordId: string;            // 业务记录ID
    action: 'create' | 'update' | 'delete'; // 操作类型
    status: 'success' | 'failed'; // 联动状态
    errorMessage?: string;       // 联动失败原因
  }>;
```

## 十一、总结

### 11.1 V2.0升级要点

| 维度 | V1.0状态 | V2.0升级 |
|------|---------|---------|
| 审批类型 | 9种（4种HR未对接） | 18种（全部对接业务） |
| 审批-业务联动 | 无 | 完整联动引擎 |
| HR审批单页面 | 独立，无业务对接 | 与人工管理模块完全对接 |
| 数据持久化 | 仅审批单持久化 | 全模块数据持久化 |
| 审批单据 | 静态展示 | 与审批状态联动，自动生成 |

### 11.2 核心改进点

1. **审批-业务联动引擎**：审批通过后自动触发业务数据更新
2. **13种新增审批类型**：覆盖人工管理所有关键业务场景
3. **审批单据联动**：审批通过后自动生成对应业务单据
4. **数据完整闭环**：从审批到业务执行到数据汇总的完整闭环
5. **可追溯性**：所有业务记录可追溯到审批单
6. **异常处理**：联动失败时记录错误，支持重新触发

### 11.3 预期效果

| 指标 | 改进前 | 改进后 |
|------|--------|--------|
| 审批与业务关联 | 无 | 100%关联 |
| 数据一致性 | 低（多份副本） | 高（单一数据源） |
| 流程自动化 | 手动操作 | 审批通过后自动联动 |
| 可追溯性 | 低 | 高（审批→业务完整链路） |
| 审批效率 | 低（需手动更新业务） | 高（一键审批，自动联动） |
