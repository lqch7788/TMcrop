# 原型演示版本地持久化方案深度对比

> 目标：从 LocalStorage（5MB限制）迁移到更可靠的本地存储，同时保持系统完整性，演示后可一键清除

---

## 一、为什么 LocalStorage 不够用

| 限制项 | LocalStorage | 影响 |
|--------|-------------|------|
| 容量上限 | ~5-10MB | 图片+大量记录很快满 |
| 同步阻塞 | 主线程同步读写 | 数据量大时UI卡顿 |
| 结构存储 | 只能存字符串 | 每次都要 JSON.stringify/parse |
| 查询能力 | 无，全靠内存过滤 | 数据多后性能断崖下降 |
| 二进制数据 | 不支持 | 图片只能转base64，体积膨胀33% |
| 事务安全 | 无 | 并发写入可能数据损坏 |

---

## 二、五大方案深度对比

### 方案A：Dexie.js（IndexedDB 高级封装）⭐ 最推荐

```
定位：纯浏览器内，零后端，容量大
原理：IndexedDB 是浏览器内置的 NoSQL 数据库，Dexie.js 给它包了一层友好 API
```

| 维度 | 详情 |
|------|------|
| 容量 | 通常 50MB~无上限（看磁盘空间） |
| 存储结构 | 对象仓库（表），支持索引、主键、复合查询 |
| 图片存储 | 支持 Blob/File 二进制直接存，不用转 base64 |
| 查询能力 | `where().equals().and().sort().limit()` 链式查询 |
| 框架兼容 | React/Vue/Angular 都支持，配合 `useLiveQuery` 实时刷新 |
| 演示后清理 | `Dexie.delete('dbName')` 一行代码清掉 |
| 向后兼容性 | 后续接后端时，只换 Service 层实现，组件不动 |

**代码示例：**
```typescript
import Dexie, { Table } from 'dexie';

// 定义数据库
class CropDB extends Dexie {
  seedSources!: Table<SeedSource>;
  seedlings!: Table<Seedling>;
  plantings!: Table<Planting>;
  dailyRecords!: Table<DailyRecord>;
  pictures!: Table<{ id: string; blob: Blob; seedlingId: string }>;

  constructor() {
    super('CropDemoDB');
    this.version(1).stores({
      seedSources: 'id, seedCode, cropCode, status, createTime',
      seedlings: 'id, seedlingCode, sourceId, cropCode, status, startDate',
      plantings: 'id, plantCode, seedlingId, cropCode, status, plantingDate',
      dailyRecords: 'id, seedlingId, recordDate',
      pictures: 'id, seedlingId'
    });
  }
}

export const db = new CropDB();

// CRUD 示例（比 LocalStorage 优雅太多）
export async function addSeedling(data: Seedling) {
  await db.seedlings.add(data);           // 新增
}

export async function getSeedlingsByCrop(cropCode: string) {
  return db.seedlings.where('cropCode').equals(cropCode).toArray();  // 索引查询
}

export async function getSeedlingsWithPagination(page: number, pageSize: number) {
  return db.seedlings
    .orderBy('createTime')
    .reverse()
    .offset((page - 1) * pageSize)
    .limit(pageSize)
    .toArray();
}

// 演示后一键清除
export async function clearAllDemoData() {
  await db.delete();  // 整个数据库删掉
  // 或者只清表：
  // await db.seedlings.clear();
}
```

**在 React 中实时同步（比 LocalStorage 的 useEffect 监听优雅）：**
```typescript
import { useLiveQuery } from 'dexie-react-hooks';

function SeedlingTable() {
  // 数据变化自动重渲染，不用手动刷新
  const seedlings = useLiveQuery(() => db.seedlings.toArray(), []);
  
  return (
    <table>
      {seedlings?.map(s => <tr key={s.id}>...</tr>)}
    </table>
  );
}
```

### 方案B：sql.js（浏览器内运行 SQLite）

```
定位：需要 SQL 能力、关系查询、复杂报表
原理：SQLite 编译成 WebAssembly，在浏览器里跑完整 SQL 引擎
```

| 维度 | 详情 |
|------|------|
| 容量 | 取决于内存，通常几百MB没问题 |
| 存储 | 内存数据库，或导出为 .db 文件 |
| SQL能力 | 完整 SQLite：JOIN、GROUP BY、子查询、事务 |
| 图片存储 | 用 BLOB 字段存二进制 |
| 迁移后端 | 极平滑——.sql 文件直接导入 MySQL/PostgreSQL |
| 演示后清理 | 删除生成的 .db 文件即可 |
| 缺点 | WASM 体积 ~1MB；查询在大数据量时比 IndexedDB 慢 |

**适用场景：**
- 需要复杂统计报表（GROUP BY、聚合函数）
- 后续确定要上关系型数据库后端
- 需要导出标准 .sql/.db 文件给其他人演示

### 方案C：Node.js + SQLite 轻量后端

```
定位：最接近真实生产架构，演示后一键删文件夹
架构：React 前端 ↔ localhost:3001 API ↔ SQLite 文件数据库
```

```
你的项目/
├── frontend/          ← React SPA（你现在的代码）
│   ├── src/
│   └── package.json
└── backend/           ← 新增：10行代码的后端
    ├── server.js      ← Express + better-sqlite3
    ├── database.db    ← SQLite 文件（演示完删掉）
    └── package.json
```

**backend/server.js（仅50行）：**
```javascript
const express = require('express');
const Database = require('better-sqlite3');
const cors = require('cors');

const app = express();
const db = new Database('database.db'); // 文件数据库，演示完删掉

app.use(cors());
app.use(express.json());

// 初始化表（自动建表）
db.exec(`
  CREATE TABLE IF NOT EXISTS seed_sources (
    id TEXT PRIMARY KEY,
    seed_code TEXT UNIQUE,
    crop_code TEXT,
    crop_name TEXT,
    quantity INTEGER,
    status TEXT,
    create_time TEXT
  );
  CREATE TABLE IF NOT EXISTS seedlings (
    id TEXT PRIMARY KEY,
    seedling_code TEXT UNIQUE,
    source_id TEXT,
    crop_code TEXT,
    initial_count INTEGER,
    survival_count INTEGER,
    status TEXT,
    start_date TEXT
  );
  -- 其他表...
`);

// 通用 CRUD 路由
const tables = ['seed_sources', 'seedlings', 'plantings', 'daily_records'];
tables.forEach(table => {
  app.get(`/${table}`, (req, res) => {
    const rows = db.prepare(`SELECT * FROM ${table}`).all();
    res.json(rows);
  });
  app.post(`/${table}`, (req, res) => {
    const cols = Object.keys(req.body).join(',');
    const placeholders = Object.keys(req.body).map(() => '?').join(',');
    const stmt = db.prepare(`INSERT INTO ${table} (${cols}) VALUES (${placeholders})`);
    stmt.run(Object.values(req.body));
    res.json({ success: true });
  });
  app.put(`/${table}/:id`, (req, res) => {
    const sets = Object.keys(req.body).map(k => `${k} = ?`).join(',');
    const stmt = db.prepare(`UPDATE ${table} SET ${sets} WHERE id = ?`);
    stmt.run(...Object.values(req.body), req.params.id);
    res.json({ success: true });
  });
  app.delete(`/${table}/:id`, (req, res) => {
    db.prepare(`DELETE FROM ${table} WHERE id = ?`).run(req.params.id);
    res.json({ success: true });
  });
});

app.listen(3001, () => console.log('Demo backend: http://localhost:3001'));
```

**前端 Service 层改造（只改这一层，页面全不动）：**
```typescript
// src/services/api.ts — 统一API客户端
const API_BASE = 'http://localhost:3001';

export async function apiGet(table: string) {
  const res = await fetch(`${API_BASE}/${table}`);
  return res.json();
}

export async function apiPost(table: string, data: any) {
  await fetch(`${API_BASE}/${table}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data)
  });
}

// src/services/seedlingService.ts — 只改这一层
export async function getSeedlings(): Promise<Seedling[]> {
  return apiGet('seedlings');  // 从 API 读
}

export async function addSeedling(data: Seedling): Promise<void> {
  await apiPost('seedlings', data);  // 通过 API 写
}
```

**启动方式：**
```bash
# 终端1
node backend/server.js

# 终端2
npm run dev   # 你的前端
```

**演示后清理：**
```bash
rm -rf backend/database.db   # 删掉数据库文件
```

### 方案D：Tauri 桌面应用 + 内嵌 SQLite

```
定位：需要打包成 .exe/.dmg 给客户演示
原理：Rust 写的轻量桌面壳，内嵌 WebView + 原生 SQLite
```

| 维度 | 详情 |
|------|------|
| 体积 | 最终打包 ~5MB（比 Electron 的 150MB 小30倍） |
| 数据库 | 原生 SQLite，性能最好 |
| 文件访问 | 能直接读写本地文件系统 |
| 演示后清理 | 删掉应用 + 数据文件夹 |
| 缺点 | 需要学 Rust 配置；构建需要 Rust 环境 |

**适用场景：**
- 需要给客户一个双击运行的 `.exe`
- 对应用体积敏感
- 后续可能发布桌面版

---

### 方案E：localForage（降级兼容方案）

```
定位：只想换掉 LocalStorage，不想学新 API
原理：封装 IndexedDB，但 API 长得像 LocalStorage
```

```typescript
import localforage from 'localforage';

// 配置不同 store
const seedlingStore = localforage.createInstance({ name: 'seedlings' });

// 异步存取
await seedlingStore.setItem('SD001', data);
const data = await seedlingStore.getItem('SD001');
```

**缺点：**
- 查询能力弱（只能 key-value，不能 `where().equals()`）
- 没有索引，大数据量时还是要全量加载到内存过滤
- 不如 Dexie.js 强大

## 三、方案选型建议

### 你的场景匹配

| 你的需求 | 最佳匹配 |
|----------|----------|
| 原型演示版，可能给客户看 | 方案A（Dexie.js）或 方案C（Node+SQLite） |
| 后续大概率上真实后端 | 方案C（Node+SQLite，迁移最平滑） |
| 不想开两个进程（前端+后端） | 方案A（Dexie.js，纯浏览器） |
| 需要复杂报表/统计 | 方案B（sql.js）或 方案C |
| 要给客户一个 .exe 文件 | 方案D（Tauri） |
| 改动最小、迁移最快 | 方案A（Dexie.js，API 最像 LocalStorage） |

### 我的推荐

**第一推荐：Dexie.js（方案A）**
- 纯浏览器，你现在 `npm run dev` 一个命令就能跑
- 容量够大（GB级别），图片直接存 Blob
- 有查询索引，分页不用全量加载
- Service 层改造后，后续接后端时只换实现，页面不动
- 演示完 `db.delete()` 一行清掉

**第二推荐：Node.js + SQLite（方案C）**
- 如果你后续后端确定用关系型数据库，这个方案最接近生产
- 前后端分离架构已经搭好，后端代码就50行
- 演示完删 `database.db` 文件即可

## 四、关键设计原则：数据访问层抽象

不管选哪个方案，**必须做这层抽象**，否则换存储时组件层全得改：

```
页面组件（SeedlingPage.tsx）
    ↓ 只依赖接口
数据服务接口（ISeedlingService）
    ↓ 两种实现
├─ LocalStorageSeedlingService（现在）
├─ DexieSeedlingService（方案A）
├─ ApiSeedlingService（方案C）
└─ SqlJsSeedlingService（方案B）
```

**接口定义：**
```typescript
// src/services/interfaces.ts
export interface ISeedlingService {
  getAll(): Promise<Seedling[]>;
  getById(id: string): Promise<Seedling | null>;
  getByCropCode(cropCode: string): Promise<Seedling[]>;
  add(data: Seedling): Promise<void>;
  update(id: string, data: Partial<Seedling>): Promise<void>;
  delete(id: string): Promise<void>;
  getPaginated(page: number, pageSize: number): Promise<{ data: Seedling[]; total: number }>;
}
```

**切换实现只需改一行：**
```typescript
// src/services/index.ts
// export { seedlingService } from './localStorageSeedlingService';
export { seedlingService } from './dexieSeedlingService';
// export { seedlingService } from './apiSeedlingService';
```

## 七、容量对比参考

| 数据类型 | LocalStorage | IndexedDB(Dexie) | SQLite |
|----------|-------------|------------------|--------|
| 1万张图片（每张1MB） | ❌ 存不下 | ✅ 10GB+ | ✅ 10GB+ |
| 10万条文本记录 | ⚠️ 接近上限 | ✅ 轻松 | ✅ 轻松 |
| 复杂查询（JOIN） | ❌ 不支持 | ⚠️ 手动实现 | ✅ 原生支持 |
| 索引查询 | ❌ 全表扫描 | ✅ 支持 | ✅ 支持 |
| 事务 | ❌ 无 | ✅ 支持 | ✅ 支持 |
| 二进制数据 | ❌ 转base64 | ✅ 原生Blob | ✅ 原生BLOB |

## 八、总结

| 场景 | 推荐方案 | 启动命令 | 清理方式 |
|------|----------|----------|----------|
| 快速原型，零后端 | **Dexie.js** | `npm run dev` | `db.delete()` |
| 需要SQL/报表/平滑迁移后端 | **Node+SQLite** | `node backend/server.js` + `npm run dev` | `rm database.db` |
| 给客户 .exe | **Tauri** | `cargo tauri build` | 删应用文件夹 |
| 最小改动 | **localForage** | `npm run dev` | `localforage.clear()` |

**我的建议：先上 Dexie.js**，你的系统现阶段最缺的是容量和查询能力，Dexie.js 完美解决这两点，改动量最小，后续切后端时只换 Service 层。

如果确定3个月内上真实后端，那就直接 **Node.js + SQLite**，架构一步到位。
