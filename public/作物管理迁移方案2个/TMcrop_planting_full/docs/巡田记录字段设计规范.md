# 巡查管理模块字段设计规范

## 1. 概述

本文档定义巡查管理模块的字段设计规范，用于指导巡查记录的管理和展示。该模块扩展了原有的"巡田监测"功能，支持多种巡查类型。

### 1.1 模块目的
- 帮助农业管理人员掌握田间状况
- 为种植人员提供数据支持
- 为公司高管提供决策参考
- 支持多种巡查类型（种植区域、设备、基础设施）

### 1.2 巡查类型

| 类型 | code | 说明 | 特定字段 |
|------|------|------|---------|
| 种植区域巡查 | farm | 农作物生长巡查 | greenhouseId, batchId, cropName, plantHeight, leafCount, soilParams |
| 设备保养巡查 | equipment | 大棚设备/农机设备保养 | equipmentId, equipmentName |
| 基础设施巡检 | infrastructure | 灌溉/排水/用电/房屋等基础设施问题 | infrastructureId, infrastructureName |

### 1.3 编号规则
**格式**: `XT` + `年月日` + `-` + `三位流水号`

**示例**: `XT20260414-001`

**规则说明**:
- `XT`: 巡田缩写，固定前缀
- `年月日`: 记录创建日期，格式 YYYYMMDD
- `三位流水号`: 每日从001开始，不足补零

## 3. 设备数据模型（Equipment）

```typescript
export interface Equipment {
  id: string;
  code: string;           // 设备编号 E001
  name: string;            // 设备名称
  type: string;            // 设备类型：水泵/电机/通风扇/卷帘机等
  location: string;         // 安装位置
  greenhouseId?: string;   // 所属温室
  status: 'normal' | 'maintenance' | 'broken';
  lastMaintenanceDate?: string;
  nextMaintenanceDate?: string;
}
```

---

## 4. 基础设施数据模型（Infrastructure）

```typescript
export interface Infrastructure {
  id: string;
  code: string;           // 设施编号 I001
  name: string;            // 设施名称
  type: string;            // 类型：灌溉/排水/供电/房屋/道路
  location: string;         // 位置描述
  greenhouseId?: string;   // 所属温室
  status: 'normal' | 'warning' | 'damaged';
}
```

## 5. 二维码方案

### 5.1 二维码内容格式

每个二维码包含 JSON 数据：

```json
{
  "type": "farm|equipment|infrastructure",
  "code": "G001|E001|P001",
  "name": "玻璃温室A区|水泵1号|主灌溉管"
}
```

### 5.2 扫码实现

- 前端使用 `html5-qrcode` 库解析二维码
- 调用手机摄像头进行扫描
- 扫码后自动解析 JSON，填充对应字段

## 6. 角色视角分析

### 6.1 农业管理人员视角

**关注重点**: 工作安排、问题跟踪、任务分配

| 优先级 | 需要的字段 | 原因 |
|--------|-----------|------|
| P0 | 巡查编号 | 便于检索和对账 |
| P0 | 巡查时间 | 精确到小时，方便安排工作 |
| P0 | 问题处理状态 | 跟踪问题处理进度 |
| P0 | 巡查类型 | 区分不同巡查内容 |
| P1 | 巡查时长 | 评估工作效率 |
| P1 | 关联批次/设备/设施 | 与生产系统关联 |

### 6.2 农业种植人员视角

**关注重点**: 记录方便、数据指导种植

| 优先级 | 需要的字段 | 原因 |
|--------|-----------|------|
| P0 | 作物状态 | 直观了解作物情况 |
| P0 | 环境参数 | 土壤EC/pH对种植决策重要 |
| P1 | 株高/叶片数 | 生长数据记录 |
| P1 | 光照/CO2 | 环境调控参考 |
| P2 | 历史同类问题 | 参考以往问题处理 |

### 6.3 公司高管视角

**关注重点**: 整体态势、异常情况、效率指标

| 优先级 | 需要的字段 | 原因 |
|--------|-----------|------|
| P0 | 巡查覆盖率 | 本月各基地巡查覆盖情况 |
| P0 | 问题数量趋势 | 病虫害增减趋势 |
| P0 | 异常占比 | 告警记录占比 |
| P1 | 人均巡查工作量 | 人员效率评估 |
| P1 | 环比/同比数据 | 与历史对比 |
| P2 | 巡查时长统计 | 工作量分析 |

## 9. 数据闭环关联

### 9.1 与生产批次关联
- 种植区域巡查可关联到具体生产批次(batchId/batchCode)
- 便于追溯该批次的生长情况

### 9.2 与农事任务关联
- 巡查记录可关联到具体任务(relatedTaskId/relatedTaskCode)
- 任务驱动型巡查有据可查

### 9.3 与设备管理关联
- 设备保养巡查关联到设备台账
- 便于设备维护历史追溯

### 9.4 与问题汇总关联
- 发现的问题自动同步到每日问题汇总
- 根据问题关键词自动判断严重程度
