## 一、验证目标概述

创建 **6 个订单**，每个订单关联 **2 个作物实例**，共 **12 个作物实例**，完整演示从订单到采收的完整数据流转过程。

### 核心验证点
1. 订单创建与实例关联
2. 种源入库与实例关联
3. 育苗管理与实例联动
4. 种植管理与实例状态更新
5. 采收管理与实例数量更新
6. 完整溯源链验证

## 二、数据架构说明

### 2.1 核心实体关系

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           实体关系图                                       │
│                                                                             │
│   CropOrder (订单)                                                          │
│       │                                                                    │
│       └── instanceIds[] ──▶ CropInstance (作物实例)                          │
│                               │                                             │
│       ┌───────────────────────┼───────────────────────┐                     │
│       │                       │                       │                     │
│       ▼                       ▼                       ▼                     │
│   SeedSource              Seedling                Planting                 │
│   (种源)                  (育苗)                  (种植)                   │
│       │                       │                       │                     │
│       └───────────────────────┴───────────────────────┘                     │
│                               │                                             │
│                               ▼                                             │
│                          HarvestRecord                                      │
│                          (采收)                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 编码规则汇总

| 实体 | 编码规则 | 示例 |
|------|---------|------|
| 品种编码 | 11位：类别(2)+类型(2)+品种(2)+子品种(3)+详细(2) | PD0301004001 |
| 实例编码 | 18位：品种编码(9)+年月日(6)+流水号(3) | PD0301000100240426001 |
| 订单编号 | DD+年月日(8)+流水号(3) | DD20260501001 |
| 种源批号 | ZZ+年月日(8)+流水号(3) | ZZ20260501-001 |
| 育苗批号 | YM+年月日(8)+流水号(3) | YM20260501-001 |
| 采收单号 | HS+年月日(8)+流水号(3) | HS20260501001 |

### 2.3 关联字段说明

| 源实体 | 目标实体 | 关联字段 | 说明 |
|-------|---------|---------|------|
| CropOrder | CropInstance | instanceIds[] | 一对多 |
| CropInstance | SeedSource | instanceId | 一对多 |
| CropInstance | Seedling | instanceId | 一对多 |

## 七、注意事项

### 7.1 数据一致性

1. **ID 生成**：使用各 Service 的 generateXxxCode() 方法自动生成
2. **关联时机**：先创建记录，再进行关联操作
3. **数量计算**：定植/采收时必须同步更新实例数量

### 7.2 编码冲突处理

由于保留现有数据，新增数据的编码需要避免冲突：
- 订单：从当日最大流水号继续
- 实例：从当日最大流水号继续
- 种源/育苗/种植：从当日最大流水号继续
- 采收：从当日最大流水号继续

### 7.3 回滚操作

如需重新开始验证，可执行以下清理操作：

```javascript
// 清理所有新增数据（保留原有数据）

## 十一、数量验证公式

### 11.1 核心验证公式

```
初始数量 - 已定植数量 - 已采收数量 = 当前剩余数量

initialQuantity - plantedQuantity - harvestedQuantity = currentQuantity
```

### 11.2 实例状态判断规则

```
if (currentQuantity <= 0) {
  status = 'harvested'  // 已采收
} else if (plantedQuantity > 0) {
  status = 'growing'  // 生长期
} else {
  status = 'seedling'  // 育苗中
}

1. 刷新页面后，前往"订单管理"查看 6 个订单
2. 前往"实例追溯"页面，点击任意实例查看溯源链
3. 验证溯源链中包含：关联订单、种源、育苗、种植、采收记录
4. 验证数量关系：`初始数量 - 已定植 - 已采收 = 当前剩余`

### 16.2 手动执行步骤（如不使用脚本）

如需手动操作，按以下顺序进行：

**步骤 1：创建订单**
- 位置：订单管理页面 → 新增订单
- 创建 6 个订单，记录订单编号

**步骤 2：创建实例**
- 位置：实例追溯页面 或 通过订单详情关联
- 每个订单创建 2 个实例，关联到对应订单

**步骤 3：创建种源**
- 位置：种源管理页面 → 新增种源
- 每个实例创建 2 条种源，关联到对应实例

**步骤 4：创建育苗**
- 位置：育苗管理页面 → 新增育苗
- 每个实例创建 1 条育苗，关联到对应种源和实例

**步骤 5：创建种植**
- 位置：种植管理页面 → 新增种植
- 每个实例创建 1 条种植，关联到对应育苗和实例

**步骤 6：采收**
- 位置：采收管理页面 → 新增采收
- 选择部分实例进行采收

**步骤 7：验证溯源**
- 位置：实例追溯页面 → 点击实例查询
