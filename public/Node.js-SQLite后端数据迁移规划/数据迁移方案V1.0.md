## 一、现状分析

### 1.1 数据存储架构概览

| 存储方式 | 模块范围 | 数据量(约) | 问题 |
|---------|---------|-----------|------|
| **LocalStorage** | 作物管理、库存V3、人事管理、审批管理、任务管理、系统设置 | ~30个数据键 | 浏览器限制、无法多端同步、数据碎片化 |

## 二、核心问题总结

### 2.1 数据存储混乱

| 问题 | 影响 |
|------|------|
| LocalStorage 和 SQLite 并存 | 维护困难，数据一致性无法保证 |
| 同一模块两套存储 | 库存有 V3 localStorage 版本和 server SQLite 版本 |
| 前后端数据不同步 | 前端操作不写入数据库，或写入后前端不感知 |

### 2.2 数据孤岛问题

```
┌─────────────────────────────────────────────────────────────────┐
│                        数据孤岛现状                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   LocalStorage                      SQLite                       │
│   ┌─────────────┐                 ┌─────────────┐             │
│   │ crop_orders │                 │crop_varieties│             │
│   └──────┬──────┘                 └──────┬──────┘             │
│          │                               │                     │
│   ┌──────┴──────┐                       │                     │
│   │crop_instances│                      │                     │
│   └──────┬──────┘                       │                     │
│          │                               │                     │
│   ┌──────┴──────┐                       │                     │
│   │   各自独立   │                       │                     │
│   │  无关联引用  │                       │                     │
│   └─────────────┘                       │                     │
│                                                                 │
│   审批数据 (LocalStorage) ──×── 业务数据 (LocalStorage/SQLite)  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 业务关联断裂

| 业务链条 | 当前状态 | 问题 |
|---------|---------|------|
| 种源 → 育苗 → 种植 → 采收 → 库存 | 理论存在 | 实际数据无外键关联 |
| 订单 → 作物实例 → 生产批次 | 理论存在 | 无 cascade 更新机制 |
| 采收 → 库存自动入库 | 断裂 | 需手动操作 |
| 任务 → 人员 → 考勤 → 工资 | 断裂 | 无关联字段 |
| 审批 → 业务数据 | 断裂 | 审批通过后业务状态未自动更新 |

## 三、数据迁移方案设计

### 3.1 总体架构目标

```
┌─────────────────────────────────────────────────────────────────────┐
│                          目标架构                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌──────────────────────────────────────────────────────────┐      │
│   │                      SQLite 数据库                         │      │
│   │  ┌─────────────────────────────────────────────────────┐│      │
│   │  │                   基础数据层                          ││      │
│   │  │  users │ departments │ warehouses │ greenhouses    ││      │
│   │  │  dictionaries │ suppliers │ employees              ││      │
│   │  └─────────────────────────────────────────────────────┘│      │
│   │  ┌─────────────────────────────────────────────────────┐│      │
│   │  │                   业务数据层                          ││      │
│   │  │  crop_orders │ crop_instances │ crop_varieties     ││      │
│   │  │  seed_sources │ seedlings │ plantings              ││      │
│   │  │  harvest_records │ inventory │ farm_tasks          ││      │
│   │  └─────────────────────────────────────────────────────┘│      │
│   │  ┌─────────────────────────────────────────────────────┐│      │
│   │  │                   流程数据层                          ││      │
│   │  │  inspections │ problems │ labor_records           ││      │
│   │  │  approvals │ workflow_configs │ audit_logs          ││      │
│   │  └─────────────────────────────────────────────────────┘│      │
│   └──────────────────────────────────────────────────────────┘      │
│                               │                                     │
│                               ▼                                     │
│   ┌──────────────────────────────────────────────────────────┐      │
│   │                    API Service Layer                       │      │
│   │              (server/src/routes/*.ts)                      │      │
│   └──────────────────────────────────────────────────────────┘      │
│                               │                                     │
│                               ▼                                     │
│   ┌──────────────────────────────────────────────────────────┐      │
│   │                   Frontend Services                       │      │
│   │     统一数据访问层，替换所有 localStorage 调用              │      │
│   └──────────────────────────────────────────────────────────┘      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 统一数据库设计

#### 3.2.1 新增系统基础表

```sql
-- 1. 用户表 (扩展现有 users)
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  username TEXT UNIQUE NOT NULL,
  password_hash TEXT,
  real_name TEXT NOT NULL,
  department_id TEXT,
  position TEXT,
  role TEXT DEFAULT 'user',
  status TEXT DEFAULT 'active',
  phone TEXT,
  email TEXT,
  avatar TEXT,
  last_login_time TEXT,
  create_time TEXT NOT NULL,
  update_time TEXT,
  FOREIGN KEY (department_id) REFERENCES departments(id)
);

-- 2. 部门表
CREATE TABLE departments (
  id TEXT PRIMARY KEY,
  department_code TEXT UNIQUE NOT NULL,
  department_name TEXT NOT NULL,
  parent_id TEXT,
  manager_id TEXT,
  status TEXT DEFAULT 'active',
  sort_order INTEGER DEFAULT 0,
  create_time TEXT NOT NULL,
  update_time TEXT,
  FOREIGN KEY (parent_id) REFERENCES departments(id)
);

-- 3. 仓库表
CREATE TABLE warehouses (
  id TEXT PRIMARY KEY,
  warehouse_code TEXT UNIQUE NOT NULL,
  warehouse_name TEXT NOT NULL,
  warehouse_type TEXT NOT NULL, -- 'seed' | 'seedling' | 'product' | 'material'
  base_id TEXT,
  location TEXT,
  capacity REAL,
  status TEXT DEFAULT 'active',
  create_time TEXT NOT NULL,
  update_time TEXT
);

-- 4. 大棚/基地表
CREATE TABLE greenhouses (
  id TEXT PRIMARY KEY,
  greenhouse_code TEXT UNIQUE NOT NULL,
  greenhouse_name TEXT NOT NULL,
  base_id TEXT,
  area_name TEXT,
  area_size REAL,
  greenhouse_type TEXT,
  status TEXT DEFAULT 'active',
  create_time TEXT NOT NULL,
  update_time TEXT
);

-- 5. 基地表
CREATE TABLE bases (
  id TEXT PRIMARY KEY,
  base_code TEXT UNIQUE NOT NULL,
  base_name TEXT NOT NULL,
  location TEXT,
  area_size REAL,
  status TEXT DEFAULT 'active',
  create_time TEXT NOT NULL,
  update_time TEXT
);

-- 6. 员工表
CREATE TABLE employees (
  id TEXT PRIMARY KEY,
  employee_code TEXT UNIQUE NOT NULL,
  employee_name TEXT NOT NULL,
  department_id TEXT,
  position TEXT,
  join_date TEXT,
  employee_type TEXT, -- 'permanent' | 'contract' | 'temporary'
  id_card TEXT,
  phone TEXT,
  emergency_contact TEXT,
  emergency_phone TEXT,
  bank_account TEXT,
  hourly_rate REAL DEFAULT 25,
  status TEXT DEFAULT 'active',
  create_time TEXT NOT NULL,
  update_time TEXT,
  FOREIGN KEY (department_id) REFERENCES departments(id)

-- 7. 供应商表 (扩展现有 suppliers)
CREATE TABLE suppliers (
  id TEXT PRIMARY KEY,
  supplier_code TEXT UNIQUE NOT NULL,
  supplier_name TEXT NOT NULL,
  supplier_type TEXT, -- 'seed' | 'material' | 'equipment'
  contact_person TEXT,
  contact_phone TEXT,
  address TEXT,
  status TEXT DEFAULT 'active',
  remarks TEXT,
  create_time TEXT NOT NULL,
  update_time TEXT
);

-- 8. 字典表
CREATE TABLE dictionaries (
  id TEXT PRIMARY KEY,
  dict_type TEXT NOT NULL, -- 字典类型编码
  dict_type_name TEXT NOT NULL, -- 字典类型名称
  dict_code TEXT NOT NULL, -- 字典项编码
  dict_value TEXT NOT NULL, -- 字典项值
  sort_order INTEGER DEFAULT 0,
  status TEXT DEFAULT 'active',
  remarks TEXT,
  create_time TEXT NOT NULL,
  update_time TEXT,
  UNIQUE(dict_type, dict_code)
);

-- 9. 审批流程配置表
CREATE TABLE workflow_configs (
  id TEXT PRIMARY KEY,
  workflow_code TEXT UNIQUE NOT NULL,
  workflow_name TEXT NOT NULL,
  workflow_type TEXT NOT NULL, -- 'leave' | 'overtime' | 'purchase' | 'material' | etc.
  steps TEXT NOT NULL, -- JSON: [{order: 1, approver_role: 'manager', approver_id: null}]
  is_active INTEGER DEFAULT 1,
  create_time TEXT NOT NULL,
  update_time TEXT
);
```

### 4.6 数据一致性保证

#### ID 映射策略

```javascript
// 建立 LocalStorage ID -> SQLite ID 映射表
const idMapping = {
  // 格式: { 'localStorage_id': 'sqlite_uuid' }
  'OLD_ID_001': 'NEW_UUID-001',
  'OLD_ID_002': 'NEW_UUID-002',
  // ...
};

// 迁移时替换所有外键引用
function migrateWithMapping(records, idMapping) {
  return records.map(record => {
    // 替换 source_id 等外键
    if (record.source_id && idMapping[record.source_id]) {
      record.source_id = idMapping[record.source_id];
    }
    // ... 其他外键替换
    return record;
  });
}
```

#### 事务性迁移

```javascript
// 伪代码：批量迁移保证一致性
async function migrateWithTransaction(dataList, tableName) {
  const db = getDatabase();
  db.run('BEGIN TRANSACTION');
  
  try {
    for (const data of dataList) {
      const newId = generateUUID();
      // 记录 ID 映射
      idMapping[data.id] = newId;
      // 替换外键后插入
      const migratedData = replaceForeignKeys(data, idMapping);
      db.run(`INSERT INTO ${tableName} VALUES (...)`, migratedData);
    }
    db.run('COMMIT');
  } catch (error) {
    db.run('ROLLBACK');
    throw error;
  }
}
```

#### 5.2.1 审批通过自动执行

```typescript
// 审批通过后触发业务动作
async function onApprovalApproved(approval: Approval) {
  switch (approval.approval_type) {
    case 'LEAVE':
      // 更新请假记录状态
      await updateLeaveRecord(approval.business_id, { status: 'approved' });
      // 更新考勤记录
      await updateAttendance(approval.applicant_id, approval.business_id);
      break;
      
    case 'OVERTIME':
      // 更新加班记录状态
      await updateOvertimeRecord(approval.business_id, { status: 'approved' });
      break;
```

### 6.4 安全策略 - 零崩溃迁移方案

**核心原则**：迁移过程不影响系统正常运行，任意阶段可回滚，迁移失败不影响原有功能。

#### 6.4.2 分阶段安全切换策略

| 阶段 | 数据层状态 | 前端行为 | 风险控制 |
|------|-----------|---------|---------|
| **S0: 准备期** | LocalStorage 为主，SQLite 空 | 所有读写走 LocalStorage | 无风险 |
| **S1: 导入期** | 后台导入 SQLite，不切换 | 所有读写仍走 LocalStorage | 无风险，数据静默迁移 |
| **S2: 灰度读** | SQLite 数据就绪 | 读优先走 SQLite，回退 LocalStorage | 低风险，可快速回退 |
| **S3: 灰度写** | 双写 LocalStorage + SQLite | 写双轨，读 SQLite | 中风险，SQLite 写入失败自动重试 |
| **S4: 全量切换** | SQLite 为主 | 所有读写走 SQLite，LocalStorage 备选 | 低风险，SQLite 故障可切回 |
| **S5: 禁用期** | 纯 SQLite | localStorage 仅作缓存/降级 | 无风险，可随时清除 |

```typescript
// 回滚触发条件
interface RollbackCondition {
  // API 错误率超过阈值
  apiErrorRateThreshold: 0.05, // 5%
  // 响应时间超过阈值
  responseTimeThreshold: 3000, // 3秒
  // 连续失败次数
  consecutiveFailuresThreshold: 3,
}

// 自动回滚执行器
class MigrationSafetyManager {
  private mode: 'S0' | 'S1' | 'S2' | 'S3' | 'S4' | 'S5' = 'S0';
  private errorCount = 0;
  private lastErrorTime = 0;
  
  // 记录 API 调用结果
  recordApiResult(endpoint: string, success: boolean, responseTime: number) {
    if (!success) {
      this.errorCount++;
      this.lastErrorTime = Date.now();
      
      // 检查是否需要回滚
      if (this.shouldRollback()) {
        this.triggerRollback();
      }
    } else {
      this.errorCount = 0;
    }
  }
  
  // 检查回滚条件
  private shouldRollback(): boolean {
    return (
      this.errorCount >= 3 ||
      (Date.now() - this.lastErrorTime) < 60000 // 1分钟内连续错误
    );
  }
  
  // 触发回滚
  private triggerRollback() {
    console.warn('[Migration] 回滚触发，切换到 LocalStorage 模式');
    this.mode = 'S0'; // 回到最安全的 S0 阶段
    localStorage.setItem('data_source_mode', 'localStorage');
  }
  
  // 获取当前数据源
  getDataSource(): 'localStorage' | 'sqlite' {
    return this.mode <= 'S2' ? 'localStorage' : 'sqlite';
  }
}
```

```typescript
// 2. 迁移中：增量同步校验
async function incrementalSync(intervalMs: number = 5000) {
  const syncState = {
    lastSyncTime: null as string | null,
    pendingChanges: [] as ChangeRecord[],
  };
  
  // Hook LocalStorage.setItem 捕获变更
  const originalSetItem = localStorage.setItem.bind(localStorage);
  localStorage.setItem = (key: string, value: string) => {
    syncState.pendingChanges.push({
      key,
      value,
      timestamp: new Date().toISOString(),
    });
    return originalSetItem(key, value);
  };
  
  // 定期同步到 SQLite
  setInterval(async () => {
    if (syncState.pendingChanges.length === 0) return;
    
    const changes = [...syncState.pendingChanges];
    syncState.pendingChanges = [];
    
    for (const change of changes) {
      await syncToSQLite(change.key, change.value);
    }
    
    syncState.lastSyncTime = new Date().toISOString();
  }, intervalMs);
}

// 3. 迁移后：数据一致性校验
async function verifyDataConsistency(): Promise<ConsistencyReport> {
  const report: ConsistencyReport = {
    totalRecords: 0,
    matchedRecords: 0,
    mismatchedRecords: [],
    missingInSQLite: [],
    missingInLocalStorage: [],
  };
  
  for (const key of ALL_STORAGE_KEYS) {
    const localData = localStorage.getItem(key);
    const sqliteData = await queryFromSQLite(key);
    
    if (!localData && !sqliteData) continue;
    
    report.totalRecords++;
    
    if (!localData && sqliteData) {
      report.missingInLocalStorage.push(key);
    } else if (localData && !sqliteData) {
      report.missingInSQLite.push(key);
    } else {
      const local = JSON.parse(localData);
      if (JSON.stringify(local) === JSON.stringify(sqliteData)) {
        report.matchedRecords++;
      } else {
        report.mismatchedRecords.push({
          key,
          localValue: local,
          sqliteValue: sqliteData,
        });
      }
    }
  }
  
  return report;
}
```

```javascript
class MigrationRunner {
  constructor(db, backupData) {
    this.db = db;
    this.backupData = backupData;
    this.idMapping = {}; // LocalStorage ID -> SQLite UUID
    this.migrationLog = [];
    this.errors = [];
  }
  
  // 生成新 UUID
  generateId() {
    return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, c => {
      const r = Math.random() * 16 | 0;
      const v = c === 'x' ? r : (r & 0x3 | 0x8);
      return v.toString(16);
    });
  }
  
  // 记录迁移日志
  log(table, action, oldId, newId) {
    this.migrationLog.push({ table, action, oldId, newId, time: new Date().toISOString() });
  }
  
  // 迁移基础数据
  async migrateBasicData() {
    console.log('开始迁移基础数据...');
    
    // 迁移字典
    const dictionaries = this.backupData['yuanxingtu_dictionaries'] || [];
    for (const item of dictionaries) {
      try {
        const newId = this.generateId();

          INSERT INTO dictionaries (id, dict_type, dict_type_name, dict_code, dict_value, sort_order, status, remarks, create_time, update_time)

      }

  }

    }
```

### 10.3 双轨数据源切换 Hook

```typescript
/**
 * 双轨数据源 Hook
 * 位置：src/hooks/useDualDataSource.ts
 */

import { useState, useEffect, useCallback } from 'react';

// 数据源模式
type DataSourceMode = 'localStorage' | 'sqlite' | 'hybrid';

interface DualDataSourceOptions<T> {
  localStorageKey: string;
  apiEndpoint: string;
  parseLocalStorage?: (data: string) => T[];
  serializeForLocalStorage?: (data: T[]) => string;
}

export function useDualDataSource<T>(options: DualDataSourceOptions<T>) {
  const [mode, setMode] = useState<DataSourceMode>(() => {
    return localStorage.getItem('data_source_mode') as DataSourceMode || 'localStorage';
  });
  
  const [localData, setLocalData] = useState<T[]>(() => {
    try {
      const raw = localStorage.getItem(options.localStorageKey);
      if (options.parseLocalStorage && raw) {
        return options.parseLocalStorage(raw);
      }
      return raw ? JSON.parse(raw) : [];
    } catch {
      return [];
    }
  });
  
  const [apiData, setApiData] = useState<T[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  
  // 切换数据源模式
  const switchMode = useCallback((newMode: DataSourceMode) => {
    setMode(newMode);
    localStorage.setItem('data_source_mode', newMode);
    
    // 记录切换日志
    console.log(`[DataSource] 切换到 ${newMode} 模式`);
  }, []);
  
  // 从 API 加载数据
  const loadFromAPI = useCallback(async () => {
    setLoading(true);
    setError(null);
    
    try {
      const response = await fetch(options.apiEndpoint);
      if (!response.ok) throw new Error(`API 错误: ${response.status}`);
      
      const data = await response.json();
      setApiData(data);
      return data;
    } catch (e) {
      const errorMsg = e instanceof Error ? e.message : '加载失败';
      setError(errorMsg);
      
      // API 失败时自动降级到 LocalStorage
      if (mode !== 'localStorage') {
        console.warn('[DataSource] API 加载失败，自动切换到 LocalStorage');
        switchMode('localStorage');
      }
      
      return null;
    } finally {
      setLoading(false);
    }
  }, [options.apiEndpoint, mode, switchMode]);
  
  // 写数据（双写）
  const writeData = useCallback(async (newData: T[]) => {
    // 1. 始终写入 LocalStorage
    try {
      if (options.serializeForLocalStorage) {
        localStorage.setItem(options.localStorageKey, options.serializeForLocalStorage(newData));
      } else {
        localStorage.setItem(options.localStorageKey, JSON.stringify(newData));
      }
      setLocalData(newData);
    } catch (e) {
      console.error('[DataSource] LocalStorage 写入失败:', e);
    }
    
    // 2. 如果是 SQLite 或 Hybrid 模式，同时写入 API
    if (mode === 'sqlite' || mode === 'hybrid') {
      try {
        await fetch(options.apiEndpoint, {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(newData),
        });
      } catch (e) {
        console.error('[DataSource] API 写入失败:', e);
        // API 写入失败不影响本地数据
      }
    }
  }, [mode, options]);
  
  // 获取当前数据（根据模式返回）
  const getData = useCallback((): T[] => {
    switch (mode) {
      case 'sqlite':
        return apiData.length > 0 ? apiData : localData;
      case 'hybrid':
        return apiData.length > 0 ? apiData : localData;
      case 'localStorage':
      default:
        return localData;
    }
  }, [mode, localData, apiData]);
  
  // 模式切换到 API 优先
  const enableSQLite = useCallback(() => {
    switchMode('sqlite');
    loadFromAPI();
  }, [switchMode, loadFromAPI]);
  
  // 回退到 LocalStorage
  const enableLocalStorage = useCallback(() => {
    switchMode('localStorage');
  }, [switchMode]);
  
  // 初始加载
  useEffect(() => {
    if (mode === 'sqlite' || mode === 'hybrid') {
      loadFromAPI();
    }
  }, []);
  
  return {
    data: getData(),
    localData,
    apiData,
    mode,
    loading,
    error,
    writeData,
    loadFromAPI,
    switchMode,
    enableSQLite,
    enableLocalStorage,
    isUsingSQLite: mode === 'sqlite' || mode === 'hybrid',
  };
}
```
