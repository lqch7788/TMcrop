# 作物多形态搜索与库存管理方案

## Context

**问题背景**：
1. 同一个作物品种（红果番茄 PD030100400）在不同阶段有不同形态：
   - 种子形态（seed）- 用于销售或育苗
   - 种苗形态（seedling）- 用于销售或定植
   - 成品形态（product）- 采收销售

2. **菜单命名问题**：
   - 当前"采收入库"菜单名称不恰当
   - 实际上这个页面应该是"作物库存中心"
   - 作用是显示所有形态（种子/种苗/成品）的库存汇总
   - 应该改名为"作物库存"作为库存中心

**最新发现的关键问题**（深入探索后补充）：

| 问题 | 说明 |
|------|------|
| **双库存体系并存** | `InventoryStock`（V3.0新）和 `ProduceInventory`（V2.0旧）是两套独立的库存结构 |
| **ProduceInventory 没有 service 层** | 直接使用 mockData，无法进行 CRUD 操作 |
| **采收数据不同步** | HarvestPage 创建的采收记录不会自动同步到 ProduceInventory |
| **数据孤岛** | ProduceInventory 使用静态 mock 数据，与业务表无关联 |

**现有问题**：
1. `ProduceInventory` 表缺少 `stockType` 字段，无法区分入库产品的形态
2. `getInventoryList` 没有 `cropName` 过滤参数，无法按作物名称搜索
3. 缺少聚合查询接口，无法一次性返回同一作物的所有形态
4. 搜索结果没有按形态分组展示
5. 菜单名称"采收入库"误导用户，实际应该是"作物库存"

**目标**：
1. 实现"搜索红果番茄时，自动显示种子/种苗/成品三种形态的结果"
2. 重构菜单名称：从"采收入库" → "作物库存"
3. 将页面定位为统一库存中心
4. **解决双库存体系问题**：统一 InventoryStock 和 ProduceInventory

## 实施计划

### Phase 0: 菜单与路由重构

**文件**: `src/App.tsx`, `src/components/layout/Sidebar.tsx`

| 改动 | 说明 |
|------|------|
| 菜单"采收入库" → "作物库存" | 更准确描述功能 |
| 路由 `/harvest` → `/crop-inventory` | 语义更清晰 |
| 页面定位调整为"统一库存中心" | 三种形态的库存汇总 |

### Phase 1: 库存体系统一（关键修复）

**问题**: 双库存体系并存导致数据不一致

**方案选择**: 采用 **渐进式统一** 策略
- `InventoryStock` 作为统一库存中心
- `ProduceInventory` 作为兼容层，逐渐向 `InventoryStock` 迁移

**修改**:
1. 为 `ProduceInventory` 添加 `stockType: StockType` 字段
2. 确保入库时数据同时写入 `InventoryStock` 和 `ProduceInventory`
3. `ProduceInventory.stockType` 默认设置为 `PRODUCT`

### Phase 2: 类型定义修改

**文件**: `src/types/inventory.ts`

| 改动 | 说明 |
|------|------|
| `ProduceInventory` 接口添加 `stockType: StockType` | 与 InventoryStock 保持一致 |
| `IInventoryStockRepository.findAll` filters 添加 `cropName?: string` | 支持按作物名称过滤 |
| 新增 `CropInventoryAggregation` 接口 | 聚合查询返回类型 |

### Phase 3: 库存服务扩展

**文件**: `src/services/inventoryService.ts`

| 改动 | 说明 |
|------|------|
| `LocalStorageStockRepository.findAll` 实现 `cropName` 过滤 | 模糊匹配 cropName |
| `getInventoryList` 函数添加 `cropName` 参数 | 暴露到服务层 |
| 新增 `searchInventoryByCropName(cropName: string)` | 按形态分组聚合查询 |

**聚合查询返回格式**:
```typescript
{
  cropName: string;
  seed: InventoryStock[];        // 种子形态
  seedling: InventoryStock[];     // 种苗形态
  product: InventoryStock[];       // 成品形态
  total: number;                 // 总记录数
  totalQuantity: {                // 各形态库存数量汇总
    seed: number;
    seedling: number;
    product: number;
  };
}
```

### Phase 4: mockData 更新

**文件**: `src/data/mockData.ts`

| 改动 | 说明 |
|------|------|
| `produceInventory` 添加 `stockType: StockType.PRODUCT` | 确保数据一致性 |

### Phase 5: 数据流打通

**问题**: 采收记录创建后未同步到 ProduceInventory

**修改**: 确保 HarvestPage 创建采收记录时，数据同时同步到：
1. `harvestService` - 保存采收记录
2. `inventoryStock` - 保存到库存中心（带 stockType）

## 数据分层搜索架构

| 搜索场景 | 数据来源 | 返回内容 |
|---------|---------|---------|
| 作物品种搜索（品种管理页面） | cropVariety | 品种编码、名称、类别等（无形态） |
| 库存搜索（库存管理页面） | InventoryStock | 按 stockType 显示实际库存（有形态） |
| 采收记录搜索 | ProduceInventory | 采收历史（含 stockType） |
| 多形态聚合搜索 | searchInventoryByCropName | 同时返回三种形态的库存 |

## 作物管理模块页面结构

| 页面 | 数据来源 | 功能说明 |
|-----|---------|---------|
| 种源管理 | seedSourceService | 种源批次，采购入库和库存记录 |

| 订单管理 | cropOrderService | 订单、交付安排和客户追溯 |

## 作物品种编码规则

**编码结构：11位 = 类别(2位) + 类型(2位) + 品种(2位) + 子品种(3位) + 详细品种(2位)**

| 段位 | 长度 | 说明 | 示例 |
|-----|-----|-----|-----|
| 类别码 | 2位 | 大类：PD=蔬菜, FR=水果, GR=粮食 | `FR` |
| 类型码 | 2位 | 中类：01=浆果类, 02=核果类 | `01` |
| 品种码 | 2位 | 小类：01=草莓, 02=蓝莓 | `01` |
| 子品种码 | 3位 | 细分品种：001=红颜, 002=章姬 | `001` |
| 详细品种码 | 2位 | 用户录入时自动分配 | `01` |

**完整示例：** `FR010100101` = 水果类-浆果类-草莓-红颜-大叶红颜
