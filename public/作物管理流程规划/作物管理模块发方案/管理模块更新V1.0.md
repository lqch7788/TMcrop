# 种植管理系统迁移规划方案

## 一、项目背景与目标

### 1.1 背景
- **旧系统** (D:\iAGS\new): 农业物联网平台，使用 EJS + jQuery EasyUI，有6个管理页面
- **新系统** (V1.1): 基于 React + TypeScript + Ant Design 的现代农业管理系统
- **目标**: 用 V1.1 替代旧管理模块，保留旧功能并进行功能增强

### 1.2 旧系统6个管理页面
| 页面 | 功能 | V1.1现状 | 规划 |
|-----|------|---------|------|
| 种源管理 | 种子/种苗采购入库 | 缺失 | **新增** |
| 育苗管理 | 育苗批次和成苗率管理 | 缺失 | **新增** |
| 种植管理 | 区域种植记录管理 | 缺失 | **新增** |
| 施肥管理 | 施肥记录管理 | 已有农事管理 | 替代 |
| 产量管理 | 产量记录管理 | 已有采收入库 | 替代 |
| 采购商管理 | 供应商管理 | 已有供应商管理 | 替代 |

## 二、系统现状分析

### 2.1 旧系统核心数据结构

**种源管理**:
- seedCode (批号), cropName (作物), seedType (类型), supplierName (供应商)
- purchaseDate, quantity, unit, availableCount, pictures

**育苗管理**:
- seedlingCode (育苗批号), sourceCode (关联种源)
- cropName, seedlingType, siteName, startDate, endDate
- initialCount, survivalCount, survivalRate, lossRate, pictures

**种植管理**:
- plantCode (种植批号), seedlingCode (关联育苗)
- cropName, areaName, plantingCount, plantingDate
- soilPH, soilEC, isHarvest, harvestDate, lossRate, pictures

### 2.2 V1.1系统架构

```
技术栈: React 18.3 + TypeScript + Vite + Ant Design + Tailwind CSS
模式: 组件化开发 (types/data/components/pages)
路由: App.tsx
菜单: Sidebar.tsx
```

## 三、菜单与路由设计

### 3.1 方案: 新建"作物管理"主菜单

**理由**: 种源、育苗、种植是农业生产的前置环节，新建独立菜单更符合业务逻辑，便于后续扩展。

### 3.2 菜单结构

```
作物管理（新增主菜单）
├── 种源管理（新增）  → /crop/seed-source
├── 育苗管理（新增）  → /crop/seedling
└── 种植管理（新增）  → /crop/planting
```

### 3.3 路由配置

```tsx
// App.tsx 新增路由
/crop/seed-source  → SeedSourcePage
/crop/seedling     → SeedlingPage
/crop/planting     → PlantingPage
```

### 3.4 图标选择

使用 Lucide React 图标，建议：
- 作物管理主菜单: `Leaf` 或 `Wheat`
- 种源管理: `Sprout`
- 育苗管理: `Flower2`
- 种植管理: `Trees`

## 四、数据模型设计

### 4.1 类型定义文件

创建 `src/types/seedling.ts`，包含:

```typescript
// 枚举
enum SeedType { SEED = 'seed', SEEDLING = 'seedling' }
enum SeedlingStatus { IN_PROGRESS, COMPLETED, CANCELLED }
enum PlantingStatus { PLANTED, GROWING, HARVESTED, CANCELLED }

// 接口
interface SeedSource {
  id, seedCode, cropCategory, cropName, seedType,
  purchaseDate, purchaserId, purchaserName,
  supplierId, supplierName, quantity, unit,
  initialCount, availableCount, unitPrice, totalAmount,
  pictures, remarks, status, createdAt, updatedAt
}

interface Seedling {
  id, seedlingCode, sourceCode, sourceId, cropName,
  seedlingType, siteId, siteName, startDate, endDate,
  initialCount, survivalCount, plantedCount,
  survivalRate, lossCount, lossRate, pictures,
  status, remarks, createdAt, updatedAt
}

interface PlantingRecord {
  id, plantCode, seedlingCode, seedlingId, sourceCode,
  cropName, variety, areaId, areaName, plantingCount,
  plantingDate, soilPH, soilEC,
  expectedHarvestDate, actualHarvestDate, harvestCount, harvestYield,
  lossCount, lossRate, pictures, status, remarks, createdAt, updatedAt
}
```

### 4.2 数据关联

```
SeedSource (种源) ──┬──→ Seedling (育苗) ──┬──→ PlantingRecord (种植)
  seedCode ─────────┘  seedlingCode ──────┘
  (库存扣减)              (成苗率计算)         (采收状态联动)
```

## 七、实施计划

### 7.1 开发阶段

| 阶段 | 模块 | 时间 | 交付物 |
|-----|------|------|-------|
| 第一阶段 | 种源管理 | 第1-2周 | 完整CRUD、库存统计、导出功能、标签打印 |
| 第二阶段 | 育苗管理 | 第3-4周 | 完整CRUD、成苗率计算、定植操作、标签打印 |
| 第三阶段 | 种植管理 | 第5-6周 | 完整CRUD、环境参数、采收联动、标签打印 |
| 第四阶段 | 关联整合 | 第7周 | 三模块联动、追溯链路、集成测试 |

### 7.2 详细任务分解

**第一阶段: 种源管理**
1. 创建类型定义 `types/seedling.ts`
2. 创建Mock数据 `data/seedlingData.ts`
3. 创建统计卡片组件 `SeedSourceStats.tsx`
4. 创建筛选工具栏 `SeedSourceFilter.tsx`
5. 创建数据表格 `SeedSourceTable.tsx`
6. 创建新增/编辑/详情弹窗
7. 创建主页面 `SeedSourcePage.tsx`
8. 配置路由和菜单

**第二阶段: 育苗管理**
1. 扩展类型定义(新增育苗相关)
2. 创建育苗管理页面组件
3. 实现成苗率自动计算
4. 实现级联选择(种源→作物自动填充)
5. 实现定植登记功能

**第三阶段: 种植管理**
1. 扩展类型定义(新增种植相关)
2. 创建种植记录页面组件
3. 实现级联选择(育苗→作物自动填充)
4. 实现环境参数记录
5. 实现采收状态联动

**第四阶段: 关联整合**
1. 实现种源→育苗→种植的追溯查询
2. 实现库存联动更新
3. 整体测试与修复
4. 文档编写


**图片上传与存储（A方案-本地文件系统）**:

**级联选择**:
```tsx
// 种源选择后自动填充作物信息
const handleSourceSelect = (sourceId: string) => {
  const source = seedSources.find(s => s.id === sourceId);
  if (source) {
    form.setFieldsValue({ cropName: source.cropName });
  }

```

**成苗率计算**:
```tsx
// 自动计算，不存储
const survivalRate = useMemo(() => {
  if (initialCount === 0) return 0;
  return (survivalCount / initialCount) * 100;
}, [initialCount, survivalCount]);
```

## 十一、风险与注意事项

1. **数据迁移**: 当前阶段不考虑，待功能完成后可设计导入工具
2. **API对接**: 前端使用Mock数据，后续对接真实API时保持接口一致
3. **标签打印**: 需要额外安装二维码生成库（如 qrcode.react）
4. **图片存储**: 需要后端配合配置静态文件服务路径
