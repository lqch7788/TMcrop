## 一、系统现状概述

### 1.1 系统定位

本系统是一个面向现代化农业种植的综合管理平台，覆盖：
- 作物种植管理（播种、生长、收获全周期）
- 农事任务管理（创建、分派、执行、验收全流程）
- 人员管理（考勤、薪酬、排班、绩效）
- 物料管理（采购、库存、领用、退回）
- 环境监测（IoT传感器、温室控制）
- 审批流程（任务审批、物料审批、采购审批）
- 巡查管理（定期巡查、问题上报、问题处理）
- 工单管理（任务派工、智能调度）
- 生产报表（成本分析、产量统计、效率评估）
- 计划管理（日计划、月计划）

### 1.2 技术栈

- **前端框架：** React 19 + TypeScript 5.8
- **状态管理：** React Hooks + LocalStorage（当前阶段）
- **UI组件：** Tailwind CSS + Lucide图标
- **构建工具：** Vite 6.2
- **数据持久化：** LocalStorage（计划后续对接后端API）

### 1.3 现有AI能力评估

| AI能力模块 | 成熟度 | 说明 |
|-----------|--------|------|
| 智能派工推荐 | ★★★☆☆ | 7因子评分算法框架，但使用Mock数据，未连接真实后端 |
| 环境异常检测 | ★★☆☆☆ | 基于阈值的规则引擎，无预测能力 |
| 病虫害预警 | ★★☆☆☆ | 关键词匹配，无法处理图像 |
| 每日/月度规划 | ★★☆☆☆ | 基础统计，无真正的AI预测 |
| 数据报表 | ★★☆☆☆ | 大量硬编码数据，无AI分析能力 |
| 考勤工时分析 | ★★☆☆☆ | 基础记录，无AI分析 |

**总体评估：** 系统AI能力处于"规则引擎+展示"阶段，缺乏预测性分析和真实AI集成。

### 1.5 当前系统局限性

1. **决策依赖人工：** 任务创建、分派、排班等主要依赖人工判断
2. **预测能力有限：** 作物生长预测仅基于简单周期模型
3. **缺乏学习能力：** 系统无法从历史数据中学习优化
4. **数据处理浅层：** 大量业务数据未被深度挖掘利用
5. **异常检测不足：** 问题发现主要依赖人工巡查
6. **优化建议规则化：** 现有AI优化仅基于固定阈值比较
7. **无自然语言处理：** 不支持语音输入、智能问答、文本分析
8. **无图像识别能力：** 无法识别病虫害照片、作物生长状态

## 三、详细AI功能需求

### 3.1 智能决策类（AI-01 ~ AI-03）

#### AI-01：智能任务分派引擎 【P0 - 最高优先级】

**业务场景：**
当前任务分派依赖管理员手动选择执行人，缺乏科学的决策依据。现有系统已有基础的评分算法（`useComprehensiveDispatch`），但算法简单，未充分利用历史数据。

**7因子评分算法现状：**
```typescript
const weights = {
  skillMatch: 0.30,           // 技能匹配度 (30%)
  location: 0.25,             // 地理位置 (25%)
  currentLoad: 0.20,          // 当前负荷 (20%)
  historicalPerformance: 0.15, // 历史表现 (15%)
  urgency: 0.10,             // 紧急程度 (10%)
  batchFamiliarity: 0.03,     // 批次熟悉度 (3%)
  weatherScore: 0.05         // 天气适配 (5%)
}
```

**AI功能需求：**

| 需求项 | 描述 | 技术要求 |
|--------|------|---------|
| 人员能力画像 | 基于历史任务完成率、效率、质量评分构建人员能力模型 | 机器学习聚类算法 |
| 智能匹配推荐 | 根据任务类型、难度、区域、时间要求，推荐最适合的执行人 | 多因子推荐算法 + 协同过滤 |
| 动态评分调整 | 根据实时因素（天气、人员疲劳度、当前工作量）动态调整推荐评分 | 实时计算引擎 |
| 学习效果反馈 | 根据任务完成结果反馈，自动调整推荐模型参数 | 强化学习/在线学习 |
| 分派方案生成 | 自动生成多个分派方案供管理员选择，并说明各方案优劣 | 多目标优化算法 |
| **任务完成时间预测** | 基于历史工时数据预测新任务完成时间 | 回归预测模型 |
| **路径优化算法** | 同一区域多个任务时计算最优执行顺序 | TSP算法/贪心算法 |

**输入数据：**
- 任务信息（类型、区域、难度、时间要求）
- 人员信息（技能、当前负荷、历史表现，出勤状态）
- 环境因素（天气，温度、季节）
- 历史数据（过往任务完成质量、效率）

**输出数据：**
- 推荐执行人列表（含匹配度评分和推荐理由）
- 分派方案（含整体效率评估）
- 风险评估（分派方案可能存在的风险）
- 预计完成时间

**集成接口：**
```typescript
interface AISmartDispatchRequest {
  taskId: string;
  taskType: string;
  area: string;
  difficulty: number;
  timeRequirement: {
    startDate: string;
    endDate: string;
    estimatedHours: number;
  };
  contextData: {
    weather: WeatherData;
    availableWorkers: WorkerInfo[];
    historicalPerformance: TaskPerformance[];
  };
}

interface AISmartDispatchResponse {
  recommendations: Array<{
    workerId: string;
    workerName: string;
    matchScore: number;
    confidenceLevel: number;
    reasoning: string;
    riskFactors: string[];
    estimatedHours: number;     // 新增：预计完成时间
    routeOptimization?: Task[];  // 新增：优化执行顺序
  }>;
  suggestedPlan: DispatchPlan;
  alternatives: DispatchPlan[];
}
```

**预期效果：**
- 分派效率提升50%（从手动选择到一键确认）
- 任务完成率提升15%
- 人员利用率提升20%
- 工时预测误差率≤20%

#### AI-02：智能人员排班系统 【P1】

**业务场景：**
人员排班需要考虑技能匹配，出勤情况，工作量均衡、个人偏好等多重因素，人工排班效率低且难以保证最优。

**AI功能需求：**

| 需求项 | 描述 | 技术要求 |
|--------|------|---------|
| 智能排班生成 | 根据任务需求、人员可用性自动生成周/月排班表 | 约束满足问题(CSP)求解器 |
| 工作量均衡 | 确保各人员工作量合理分配，避免过度劳累 | 优化算法 |
| 技能匹配优化 | 确保每个班次都有合适技能的人员覆盖 | 图算法/匹配算法 |
| 冲突检测 | 自动检测排班冲突（时间、人员、技能） | 规则引擎 |
| 排班调整建议 | 当出现突发情况（请假、紧急任务）时，自动给出调整方案 | 实时重调度算法 |

**输入数据：**
- 任务计划（时间、区域、所需技能、人数要求）
- 人员信息（技能、可用时间、偏好、限制条件）
- 历史排班数据
- 考勤数据（出勤率、请假记录）

**输出数据：**
- 排班表（按天/周/月）
- 人员分配明细
- 冲突检测报告
- 调整建议

### 3.2 智能预测类（AI-04 ~ AI-06）

#### AI-04：作物生长预测系统 【P0】

**业务场景：**
当前作物生长预测仅基于固定周期模型（`useCropGrowthEngine`），未考虑实际环境因素和作物状态，预测精度有限。

**AI功能需求：**

| 需求项 | 描述 | 技术要求 |
|--------|------|---------|
| 生长阶段预测 | 基于实时环境数据预测作物生长阶段和进度 | 时间序列预测/LSTM |
| 产量预测 | 基于历史产量、环境、管理水平预测最终产量 | 回归预测模型 |
| 生长异常预警 | 当实际生长偏离预期时发出预警 | 异常检测 |
| 生长影响因素分析 | 分析哪些因素对生长影响最大，给出优化建议 | 特征重要性分析 |
| 多场景模拟 | 模拟不同管理策略下的生长结果，辅助决策 | 仿真模拟 |

**输入数据：**
- 作物信息（品种、种植日期、当前生长阶段）
- 环境数据（温度、湿度，光照、CO2浓度）
- 农事操作记录（施肥、灌溉、打药等）
- 历史产量数据
- 土壤数据（如有）

**输出数据：**
- 生长进度预测（含置信区间）
- 预计成熟日期
- 预计产量范围
- 异常预警信息
- 优化建议

**预期效果：**
- 产量预测准确率提升至85%+
- 异常生长发现提前3-5天
- 种植计划准确率提升25%

| 预防措施推荐 | 根据预测结果推荐预防措施 | 推荐系统 |

**输入数据：**

**预期效果：**

### 3.4 智能识别类（AI-09 ~ AI-10）

#### AI-09：病虫害图像识别系统 【P1】

**业务场景：**
巡查人员发现作物异常时拍照上传，系统应能自动识别病虫害类型和严重程度。

**AI功能需求：**

| 需求项 | 描述 | 技术要求 |
|--------|------|---------|
| 病虫害类型识别 | 通过照片识别病虫害类型 | 图像分类模型 |
| 严重程度评估 | 评估病虫害的严重程度 | 图像分割/分类 |
| 相似案例匹配 | 匹配历史相似案例供参考 | 图像检索 |
| 防治方案推荐 | 根据识别结果推荐防治方案 | 知识图谱 |
| 识别置信度 | 给出识别结果的置信度，低置信度时建议人工确认 | 置信度评估 |

**技术要求：**
- 模型类型：CNN/ResNet/EfficientNet等
- 训练数据：需要大量病虫害标注照片（>5000张）
- 部署方式：云端API或边缘计算
- 识别响应时间：<3秒

**集成接口：**
```typescript
interface PestIdentificationRequest {
  image: File | base64;
  greenhouseId?: string;
  cropType?: string;
}

interface PestIdentificationResponse {
```

### 4.2 前端SDK集成方式

```typescript
// AI服务SDK集成模式

// 1. 创建AI服务实例
const aiService = createAIService({
  baseUrl: 'https://ai-service.greenhouse.com/api/v1',
  apiKey: process.env.AI_API_KEY,
  timeout: 30000,
});

// 2. 在组件中使用AI功能
function TaskDispatchPage() {
  const [recommendations, setRecommendations] = useState<WorkerRecommendation[]>([]);
  const [loading, setLoading] = useState(false);

  const handleSmartDispatch = async (taskId: string) => {
    setLoading(true);
    try {
      const result = await aiService.smartDispatch({
        taskId,
        contextData: await buildDispatchContext(taskId),
      });
      setRecommendations(result.recommendations);
    } catch (error) {
      // 降级到本地算法
      const fallback = useLocalRecommendAlgorithm(taskId);
      setRecommendations(fallback);
    } finally {
      setLoading(false);
    }
  };

  return (
    <div>
      {loading ? <LoadingSpinner /> : <RecommendationList recommendations={recommendations} />}
    </div>
  );
}
```

### 4.3 降级策略

为保证系统可用性，所有AI功能必须具备降级能力：

| 场景 | 降级方案 |
|------|---------|
| AI服务不可用 | 使用本地规则算法（如现有的7因子评分） |
| AI响应超时 | 返回缓存结果或使用规则引擎 |
| 模型版本异常 | 自动回滚到上一稳定版本 |
| 识别置信度低 | 标记为"需要人工确认" |
