# 种植管理系统全生命周期规划

## Context

种植管理系统当前由多个相对独立的模块组成：**生产计划、种源管理、育苗管理、种植管理、采收入库**。这些模块各自运作，数据不互通，形成了"数据孤岛"问题。

**核心架构（已确认）**：

本系统的**双核心驱动**架构：
1. **品种库** = 品种数据的 Single Source of Truth（所有作物品种名称和编码都从品种库获取）
2. **生产计划** = 所有生产活动的指挥棒（种源采购、育苗、定植、采收都要依据计划）

**现有数据模型分析**：

| 模块 | 关键字段 | 与双核心关联 | 问题 |
|------|---------|------------|------|
| 作物品种库 | cropCode(11位), 生长周期参数 | 品种数据基础 | 系统基础表 |
| 生产计划 | batchId, planCode, items | 驱动所有下游模块 | **与下游完全脱节** |
| 种源管理 | varietyId, varietyName | 品种库 + 依计划采购 | **未继承品种参数** |
| 育苗管理 | seedId, varietyId | 品种库 + 依计划培育 | **未基于品种参数推算** |
| 种植管理 | seedlingId, varietyId | 品种库 + 依计划定植 | **无品种参数传递** |
| 采收入库 | variety (名称) | 品种库 + 依计划采收 | **无完整追溯链** |

**发现的关键问题**：

1. **生产计划与下游完全脱节** - 计划批准后没有触发任何下游动作
2. **品种库生长周期参数未被使用** - 品种库有参数但下游模块没有继承
3. **品种选择存在不一致** - 部分模块用 varietyId，部分用 varietyName
4. **追溯链不完整** - 采收入库只能看到品种名称，无法追溯到种源、育苗批次

**规划目标**：
1. **双核心驱动** - 品种库 + 生产计划共同驱动所有下游模块
2. **计划贯穿全程** - 种源采购、育苗培育、定植、采收都依据生产计划
3. **全流程可视化** - 实现从计划到采收的全流程追踪和可视化
4. **质量追溯** - 实现农产品全生命周期质量追溯

## 完整数据流转设计（双核心驱动 + 循环闭环）

```
                         ┌─────────────────────────────────────────┐
                         │           作物品种管理库                 │
                         │   (系统设置 - 品种数据 Single Source)    │
                         │   - 品种编码（11位）                    │
                         │   - 生长周期参数                        │
                         │   - 环境参数（温度/PH/EC）              │
                         └─────────────────┬───────────────────────┘
                                           │
                    ┌──────────────────────┴──────────────────────┐
                    │                 生产计划                     │
                    │        (所有生产活动的指挥棒)                │
                    │  - 年度生产规划                              │
                    │  - 批次计划（种源/育苗/种植/采收）           │
                    │  - 技术方案配置                              │
                    │  - 采购需求生成                              │
                    └────────────┬───────────────────────────────┘
                                 │
          ┌───────────────────────┼───────────────────────┐
          │                       │                       │
          ▼                       ▼                       ▼
┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
│     种源管理     │   │     育苗管理     │   │     种植管理     │
│                 │   │                 │   │                 │
│ 依计划采购入库   │   │ 依计划培育      │   │ 依计划定植      │
│ 依品种库选品种   │   │ 依品种库定参数   │   │ 依品种库管理    │
└────────┬────────┘   └────────┬────────┘   └────────┬────────┘
         │                     │                     │
         │                     │                     │
         │◀────────────────────┴─────────────────────┤
         │              (采收种子/苗可回到种源/育苗)     │
         │                                               │
         └───────────────────────┬───────────────────────┘
                                 ▼
                    ┌─────────────────┐
                    │     采收入库    │
                    │                 │
                    │  种子/种苗/成品 │
                    │  可回流闭环     │
                    └─────────────────┘

                    循环闭环说明：
                    ┌─────────────────────────────────────────┐
                    │  采收种子 → 种源入库（种子库）           │
                    │  采收种苗 → 育苗入库（待定植）           │
                    │  采收成品 → 产品入库（销售/库存）        │
                    └─────────────────────────────────────────┘
```

**核心数据流向**：
- 品种库 → 为所有模块提供品种数据
- 生产计划 → 驱动所有模块的生产活动
- 各模块 → 执行计划、记录实际、积累数据
- **循环闭环** → 采收产物可回流到上游库存

## 核心数据联动设计

### 联动0：生产计划 → 各模块（核心驱动器）

**生产计划的职责**：
1. 制定年度/季度生产规划
2. 创建具体批次计划（包含品种、数量、时间节点）
3. 分解任务：种源采购需求、育苗需求、种植需求、采收需求
4. 跟踪执行进度，监控各模块完成情况

**批次计划结构**：
```typescript
interface ProductionBatchPlan {
  batchId: string;                 // 批次ID
  batchCode: string;              // 批次编号（SC + 年月日 + 序号）
  year: number;                   // 生产年份
  season: string;                  // 季节
  cropCode: string;               // 品种编码（11位）
  varietyName: string;            // 品种名称
  plannedQuantity: number;         // 计划数量
  unit: string;                   // 单位
  seedPurchaseDate?: string;      // 计划种源采购日期
  seedlingStartDate?: string;      // 计划育苗开始日期
  plantingDate?: string;           // 计划定植日期
  expectedHarvestDate?: string;    // 预计采收日期
  status: 'draft' | 'approved' | 'in_progress' | 'completed' | 'cancelled';
}
```

### 联动1：品种库 → 种源管理（自动继承 + 必填关联 + 来源区分 + 供应商验证）

**触发时机**：种源入库时选择品种后

**新增必填关联**：
- `productionBatchId`: 关联的生产批次计划（**必填**）
- `productionBatchCode`: 关联的批次编号

**新增来源区分 + 供应商验证**：
- `sourceType`: 'self_produced' | 'external_purchased' （**自产/外购**）
- `supplierId`: 供应商ID（**必填**）
- `supplierName`: 供应商名称
- `purchaseOrderNo`: 采购单号
- `baseId`: 基地ID（**自产时必填**）
- `baseName`: 基地名称（**自产时必填**）

**供应商验证规则**：
- 外购时必须从"库存管理-供应商管理"中选择供应商
- 如果没有供应商记录，必须先到供应商管理添加后再回来创建外购种源
- 自产时：
  - 供应商字段填充为公司名称（从系统设置获取）
  - `baseId` 和 `baseName` 必须填写，区分是哪个基地自产的
  - 方便集团模式下多基地区分

**种源入库记录**：
```typescript
interface SeedSourceRecordExtension {
  productionBatchId: string;         // 关联生产批次（必填）
  productionBatchCode: string;
  sourceType: 'self_produced' | 'external_purchased'; // 来源类型
  supplierId: string;               // 供应商ID（必填）
  supplierName: string;             // 供应商名称（必填）
  purchaseOrderNo: string;          // 采购单号（外购时必填）
  baseId: string;                  // 基地ID（自产时必填）
  baseName: string;                // 基地名称（自产时必填）
}
```

**追溯链**：
```
种源入库（外购） → 供应商信息 → 供应商管理记录
                → 采购单号
                → 品种信息
                → 生产批次计划

种源入库（自产） → 基地信息 → 基地管理记录
                → 公司名称
                → 品种信息
                → 生产批次计划
```

### 联动2：育苗管理（统一入库模式）

**设计原则**：无论种源来自何处，都必须先在"种源管理"完成入库登记

**育苗种源来源**：
- **系统内种源** - 从种源库调拨（已入库的种源）
- **外部采购种源** - 先在种源管理入库，再调拨给育苗

**育苗流程**：
1. 种源入库时标记来源（自产/外购）
2. 育苗时选择已入库的种源 → 关联种源记录
3. 自动扣减种源库存

**育苗记录**：
```typescript
interface SeedlingRecordExtension {
  seedId: string;                  // 关联种源ID（必填，必须是已入库的种源）
  seedCode: string;               // 关联种源批号
  productionBatchId?: string;      // 关联生产批次（必填）
  productionBatchCode?: string;
}
```

### 联动3：种植管理（统一入库模式）

**设计原则**：无论种苗来自何处，都必须先完成入库登记

**种植种苗来源**：
- **系统内育苗** - 使用已入库的育苗批次
- **系统内种源** - 直接用已入库的种源播种（不经过育苗）

**种植流程**：
1. 种植时选择已入库的种源或育苗
2. 记录来源
3. 关联相应的入库记录

**种植记录**：
```typescript
interface PlantingRecordExtension {
  sourceType: 'seedling' | 'seed';  // 来源类型：苗/种子
  seedlingId?: string;              // 关联育苗ID（用苗时必填）
  seedlingCode?: string;
  seedId?: string;                  // 关联种源ID（用种时必填）
  seedCode?: string;
  productionBatchId?: string;       // 关联生产批次（必填）
  productionBatchCode?: string;
}
```

### 联动4：采收入库（统一入库 + 循环闭环 + 来源区分 + 供应商/基地验证）

**设计原则**：无论产物来自何处，都必须先完成入库登记，并区分来源

**入库类型**：
1. **种子入库** - 采收的是种子，入库到**种源库存**（形成循环）
2. **种苗入库** - 采收的是种苗，入库到**育苗库存**（待定植，形成循环）
3. **成品入库** - 采收的是成品作物，入库到**产品库存**

**来源区分 + 供应商/基地验证**：
- `sourceType`: 'self_produced' | 'external_purchased'
- `supplierId`: 供应商ID（**必填**）
- `supplierName`: 供应商名称
- `purchaseOrderNo`: 采购单号
- `baseId`: 基地ID（**自产时必填**）
- `baseName`: 基地名称（**自产时必填**）

**供应商/基地验证规则**：
- 外购时必须从"库存管理-供应商管理"中选择供应商
- 自产时：
  - 供应商字段填充为公司名称
  - `baseId` 和 `baseName` 必须填写，区分是哪个基地的

**采收入库流程**：
1. 种子采收 → 在种源管理创建入库记录（标记自产/外购 + 基地验证）
2. 种苗采收 → 在育苗管理创建入库记录（标记自产/外购 + 基地验证）
3. 成品采收 → 在产品库存创建入库记录（标记自产/外购 + 基地验证）

**采收记录**：
```typescript
interface HarvestRecordExtension {
  harvestType: 'seed' | 'seedling' | 'product'; // 采收类型
  sourceType: 'self_produced' | 'external_purchased'; // 来源类型
  supplierId: string;               // 供应商ID（必填）
  supplierName: string;             // 供应商名称（必填）
  purchaseOrderNo: string;          // 采购单号（外购时必填）
  baseId: string;                  // 基地ID（自产时必填）
  baseName: string;                // 基地名称（自产时必填）
  plantingId?: string;              // 关联种植记录
  plantingCode?: string;
  seedlingId?: string;               // 关联育苗记录
  seedlingCode?: string;
  seedId?: string;                   // 关联种源记录
  seedCode?: string;
  productionBatchId?: string;        // 关联生产批次
  productionBatchCode?: string;
  cropCode: string;                  // 品种编码（11位）
  traceCode: string;                 // 追溯码
  targetInventory: 'seed' | 'seedling' | 'product'; // 目标库存
}
```

**全程追溯链**：
```
外购追溯链：
  外购入库 → 供应商信息 → 供应商管理记录
          → 采购单号
          → 品种信息
          → 生产批次计划

自产追溯链：
  自产入库 → 基地信息 → 基地管理记录
          → 公司名称
          → 品种信息
          → 生产批次计划
```

### 联动5：完整追溯链

**追溯方向**：从任意节点可以追溯完整生命周期

```
生产计划批次
    │
    ├──→ 种源记录 ──→ 育苗批次 ──→ 种植记录 ──→ 采收记录
    │
    │（外部采购的种源/种苗也是先入库，形成追溯链起点）

采收入库追溯：
    ├── 种子入库 → 可追溯：来源种植 → 育苗/种源 → 品种 → 生产批次
    ├── 种苗入库 → 可追溯：来源种植 → 育苗 → 品种 → 生产批次
    └── 成品入库 → 可追溯：种植 → 育苗/种源 → 品种 → 生产批次
```

## 核心模块规划

### 1. 作物品种管理库（基础层）

**定位**：Single Source of Truth，所有模块的数据基础

**核心能力**：
- 品种编码体系（11位：类别+类型+品种+子品种1+详细品种）
- 生长周期参数配置（发芽期、育苗期、开花期、结果期、摘收期）
- 环境参数标准（空气温度、土壤PH、土壤EC值）
- 品种状态管理（active/inactive）

**下游联动**：
- 种源入库时选择品种 → 自动继承生长周期参数
- 育苗计划基于品种的生长周期自动推算
- 种植管理基于品种参数进行农事提醒
- 采收入库时关联品种进行质量评级

### 2. 生产计划模块

**定位**：年度生产规划的制定与管理

**核心功能**：
- 年度生产计划制定
- 生产批次规划（按品种、按基地、按季节）
- 技术方案配置（关联品种的生长周期和环境参数）
- 种植日历生成（基于品种参数自动推算各阶段时间节点）

**下游联动**：
- 计划批准后 → 自动在种源管理创建采购需求
- 批次计划 → 指导种源采购数量和育苗数量

### 3. 种源管理模块

**定位**：种子/种苗的采购入库和库存管理

**核心功能**：
- 供应商管理
- 采购订单管理
- 种子/种苗入库（关联品种，继承生长周期参数）
- 库存管理（可用数量、已分配数量、已使用数量）
- 出库记录（向育苗模块出库）

**上下游联动**：
- 接收生产计划的采购需求
- 入库时自动继承品种的生长周期和环境参数
- 出库时扣减库存并记录去向（流向育苗模块）
- 库存不足时自动预警

### 4. 育苗管理模块

**定位**：从种子/种苗到可定植苗株的全过程管理

**核心功能**：
- 批次管理（批次号、品种、来源种源、入库时间）
- 生长记录（日常记录、生长状态跟踪）
- 育苗周期跟踪（基于品种参数的预期vs实际对比）
- 定植操作（确认苗株可定植，流向种植模块）

**上下游联动**：
- 入圃时关联种源 → 自动继承品种信息
- 入圃时扣减对应种源的可用数量
- 定植确认时 → 在种植管理创建种植记录
- 定植后标记种源的使用完成状态

### 5. 种植管理模块

**定位**：从定植到采收的全程管理

**核心功能**：
- 定植记录（关联育苗批次、品种、地块）
- 农事活动记录（施肥、灌溉，病虫害防治等）
- 生长周期跟踪（与品种参数对比，预警偏差）
- 采收计划（预计采收时间、预计产量）
- 实际采收记录（触发采收入库流程）

**上下游联动**：
- 接收育苗模块的定植确认
- 品种信息来自品种库（品种参数贯穿全流程）
- 采收时 → 在采收入库模块创建采收记录

### 6. 采收入库模块

**定位**：采收后的质量检测和入库管理

**核心功能**：
- 采收记录（关联种植记录、品种、实际产量）
- 质量检测（等级评定、合格判定）
- 入库管理（仓库位置、库存数量）
- 质量追溯（关联种植批次、育苗来源、种源信息）

**上下游联动**：
- 接收种植模块的采收触发
- 关联品种信息用于质量评级
- 可反向追溯：采收 → 种植 → 育苗 → 种源 → 品种

## 技术方案（简化版 - 统一入库模式）

### 核心设计原则

**统一入库**：所有物资（种源、种苗、成品）无论来源，都必须先完成系统内入库登记
- 外部采购 → 直接在对应模块创建入库记录
- 系统内培育 → 通过系统流程自动创建记录
- 采收产物 → 通过采收流程创建入库记录
