# 农事管理模块整合规划方案

## Context

**问题背景**：
当前农事管理模块存在以下问题：
1. **页面过多**：7个独立页面（任务派发、农事操作记录、问题分派、巡查管理、采收入库、每日工单汇总、任务中心）
2. **功能分散**：任务、问题、巡查、操作记录分散在不同页面
3. **数据流交叉**：巡查→问题→任务→操作记录的数据流不够清晰
4. **操作不便**：缺乏统一入口，用户需要在多个页面间跳转

**整合目标**：
- 提供统一的操作入口
- 清晰的数据流转
- 减少页面跳转
- 提升操作效率

**⚠️ 核心约束（最高优先级）**：
- **不得改变现有农事管理所有页面的数据和后台业务流程**
- **不得修改现有页面功能、状态流转逻辑、数据存储结构**
- **不得影响现有业务数据流和操作记录**
- 新增的 FarmTaskHub 是**新增页面**，原有7个页面保持不变
- 整合是**界面聚合**，不是**业务重构**
- 原有页面继续作为独立入口，FarmTaskHub作为统一入口补充

## 一、当前页面结构

```
农事管理/
├── 任务派发 (TaskDispatchPage)        - 任务CRUD、状态流转
├── 农事操作记录 (AgricultureRecordPage) - 操作记录汇总展示
├── 问题分派 (ProblemDispatchPage)     - 巡查问题管理
├── 巡查管理 (InspectionPage)          - 巡查记录
├── 采收入库 (HarvestPage)            - 采收管理
├── 每日工单汇总 (DailyWorkSummary)   - 汇总统计
└── 任务中心 (TaskCenterPage)        - 任务聚合（我的任务/工作日志/智能派工）
```

## 三、数据结构设计

### 3.1 核心数据类型

```typescript
// ============================================
// 农事任务中心 - 统一数据结构
// ============================================

/**
 * 统一任务项 - 任务中心核心数据类型
 * 整合了原Task和ProblemEntry的结构
 */
interface UnifiedTaskItem {
  // 基础标识
  id: string;
  code: string;                    // 统一编号：TK-任务, PD-问题, SP-巡查

  // 类型区分
  itemType: 'task' | 'problem' | 'inspection';
  
  // 基本信息
  title: string;                   // 标题
  description?: string;           // 描述
  sourceModule?: 'farm' | 'temp' | 'problem' | 'inspection';  // 来源模块
  sourceId?: string;               // 来源ID
  
  // 执行信息
  assigneeId?: string;            // 执行人ID
  assigneeName?: string;          // 执行人姓名
  assignedAt?: string;            // 分派时间
  
  // 状态与进度
  status: TaskStatus;             // 统一状态
  progress?: number;             // 进度 0-100
  priority: 'urgent' | 'high' | 'medium' | 'low';
  
  // 时间和区域
  plannedDate?: string;           // 计划日期
  dueDate?: string;               // 截止日期
  completedAt?: string;           // 完成时间
  workZone?: string;              // 工作区域
  greenhouse?: string;            // 温室
  
  // 业务特定
  taskType?: FarmOperationType;  // 任务类型（灌溉/施肥/植保等）
  problemSeverity?: '轻微' | '中等' | '严重';  // 问题严重程度
  inspectionType?: InspectionType; // 巡查类型
  
  // AI相关
  aiRecommended?: boolean;         // 是否AI推荐
  aiConfidenceScore?: number;      // AI置信度
  aiRecommendationReason?: string; // AI推荐理由
  
  // 操作记录
  operationRecords: OperationRecord[];
  
  // 元数据
  createdAt: string;
  createdBy: string;
  updatedAt: string;
}

/**
 * 任务状态枚举
 */
type TaskStatus = 
  | 'draft'           // 草稿
  | 'pending'         // 待接受（已派发）
  | 'accepted'        // 已接受
  | 'in_progress'     // 进行中
  | 'pending_verify'   // 待验收
  | 'completed'        // 已完成
  | 'cancelled'        // 已取消
```

## 五、整合方案

### 5.1 方案设计思路

将农事管理重构为 **"一个中心 + 三个入口"** 的架构：

> **⚠️ 重要说明**：本方案是**界面整合**，不是**业务重构**。所有原有页面的功能、数据、业务流程保持不变。
> - FarmTaskHub 是**新增的统一入口页面**
> - 原有7个页面**继续保留和使用**，不做任何修改
> - 新页面读取现有数据结构，不改变原有数据存储

### 核心页面重构

## 七、风险评估与应对

### 7.1 核心原则

> **本方案是界面整合，不是业务重构。所有原有功能、数据、业务流程保持不变。**

### 7.2 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 新页面读取数据失败 | 中 | 低 | 复用现有hooks和数据接口 |
| 状态显示不一致 | 低 | 低 | FarmTaskHub为只读展示，不修改状态 |

### 7.3 业务风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 影响现有用户操作 | 低 | 极低 | 新增入口可选使用，不强制替换 |
| 数据展示不完整 | 中 | 低 | 完整对接现有所有数据接口 |

### 7.4 实施策略

1. **纯新增**：只新增FarmTaskHub页面，不修改任何现有代码
2. **读取现有数据**：新页面读取现有hooks和数据，不创建独立数据源
3. **可选入口**：用户在原有页面或新统一入口均可完成相同操作
