## 一、项目背景与目标

### 1.1 项目背景

人工管理模块是种植管理系统的重要组成部分，涵盖了从员工入职到离职的完整生命周期管理。当前模块存在以下问题：

1. **数据孤岛问题**：临时工和正式员工数据分离，各子模块数据无法共享
2. **硬编码严重**：HrApprovalDocuments、HrAttendance等页面存在大量硬编码数据
3. **业务流程断裂**：请假/加班申请与审批流程未完全打通
4. **组件重复**：批量编辑、导出、分页等组件在每个模块重复实现
5. **HR审批单功能缺失**：新增、编辑、查看按钮无实际功能

### 1.2 项目目标

本次优化的核心目标是：

1. **数据连通**：建立统一的员工主数据模型，实现各模块数据共享
2. **流程顺通**：梳理并打通从入职到离职的完整业务流程
3. **体验优化**：统一组件设计，提升用户体验
4. **业务闭环**：实现请假/加班/调岗/离职等业务的完整审批闭环

### 1.3 目标用户

| 用户角色 | 需求描述 |
|---------|---------|
| **普通员工** | 提交请假/加班申请、查看工资、查看考勤记录 |
| **班组长** | 查看组员考勤、审批组员申请、安排排班 |
| **人事专员** | 员工入职办理、合同管理、HR审批 |
| **人事经理** | 部门人事管理、薪资核算、报表分析 |
| **系统管理员** | 部门/岗位配置、权限管理、系统设置 |
| **财务人员** | 工资发放、社保公积金核算 |

## 二、现有问题深入分析

### 2.1 HR审批单页面详细分析

#### 2.1.1 HrApproval.tsx 页面分析

**表格字段：**

| 字段 | 数据类型 | 数据来源 | 问题 |
|------|----------|----------|------|
| code | string | Approval.code | 正常 |
| applicantName | string | Approval.applicantName | 正常 |
| type | ApprovalType | Approval.type | 正常 |
| applyDate | string | Approval.applyDate | 正常 |
| status | ApprovalStatus | Approval.status | 正常 |
| id | string | Approval.id | 正常 |

**问题：**
- 查看按钮仅有UI无实际跳转逻辑
- 审批操作通过/拒绝无确认弹窗
- 状态筛选缺少"已拒绝"选项

**数据流：**
```
ApprovalContext (localStorage持久化)
    ↓ useHrApprovals() hook
    ↓ 过滤: category === 'hr'
    ↓ 按type再分类: LEAVE/OVERTIME/TRANSFER/RESIGN
HrApproval.tsx
```

#### 2.1.2 HrApprovalDocuments.tsx 页面分析

**表格字段：**

| 字段 | 数据类型 | 数据来源 | 问题 |
|------|----------|----------|------|
| code | string | 硬编码 | ❌ 需从业务数据获取 |
| type | string | 硬编码 | ❌ 需定义为枚举 |
| applicant | string | 硬编码 | ❌ 需关联Worker |
| dept | string | 硬编码 | ❌ 需关联Department |
| applyDate | string | 硬编码 | 正常 |
| targetTime | string | 硬编码 | ❌ 需关联业务 |
| reason | string | 硬编码 | ❌ 需关联业务 |
| status | string | 硬编码 | ❌ 需统一状态枚举 |

**严重问题：**
1. **第5-11行硬编码数据**：`hrDocuments`数组直接写在组件内
2. **功能全部缺失**：新增、编辑、查看按钮仅有图标无功能
3. **筛选无效**：下拉选择器change事件未触发实际筛选
4. **数据冗余**：`status`和`statusClass`重复存储

#### 2.1.3 HrAttendance.tsx 页面分析

**表格字段：**

| 字段 | 数据类型 | 数据来源 | 问题 |
|------|----------|----------|------|
| workerName | string | 硬编码 | ❌ 需关联Worker |
| department | string | 硬编码 | ❌ 需关联Department |
| date | string | 硬编码 | 正常 |
| checkIn | string | 硬编码 | ❌ 需关联Attendance |
| checkOut | string | 硬编码 | ❌ 需关联Attendance |
| status | string | 硬编码 | ❌ 需统一状态枚举 |
| hours | string | 硬编码 | ❌ 需计算 |

**严重问题：**
1. **第7-14行硬编码数据**：所有考勤数据写死在组件内
2. **部门选项硬编码**：第17-20行 `departmentOptions`
3. **日期选择器无功能**：仅显示，无筛选逻辑

### 2.2 数据孤岛问题

| 孤岛页面 | 问题描述 | 联动影响 |
|---------|---------|---------|
| LeavePage | 请假数据独立，不经过审批系统 | 考勤系统无法获取已批假数据 |
| OvertimePage | 加班数据独立，不经过审批系统 | 工资系统无法获取加班数据 |
| RecruitmentPage | 招聘申请独立，无审批流程 | 入职流程无法触发 |
| HrApprovalDocuments | 考勤单据独立数据源 | 与LeavePage/OvertimePage数据不同步 |

### 2.3 员工ID体系混乱

| 格式 | 来源 | 问题 |
|-----|------|-----|
| S001/S002 | LeavePage, OvertimePage | 不统一 |
| W001/W002 | 其他页面 | 不统一 |
| EMP001/EMP002 | 员工档案 | 标准格式 |

**解决方案**: 统一为 `EMP-YYYYMMDD-XXX` 格式

### 2.4 缺失的审批类型

当前仅有4种审批类型，需扩展到10种：

| # | 审批类型 | 说明 | 优先级 |

| 2 | 加班申请 | 现有 | P0 |
| 3 | 离职申请 | 现有 | P0 |
| 4 | 招聘申请 | 现有 | P0 |
| 5 | 入职办理 | **新增** | P1 |
| 6 | 考勤补录 | **新增** | P1 |
| 7 | 调薪申请 | **新增** | P2 |
| 8 | 合同续签 | **新增** | P2 |
| 9 | 工资预算 | **新增** | P2 |

### 3.1 审批类型枚举定义

```typescript
// src/types/approval.ts

export enum ApprovalType {
  LEAVE = 'leave',                           // 请假申请
  OVERTIME = 'overtime',                     // 加班申请
  RESIGNATION = 'resignation',               // 离职申请
  RECRUITMENT = 'recruitment',             // 招聘申请
  ONBOARDING = 'onboarding',               // 入职办理
  ATTENDANCE_REPAIR = 'attendance_repair', // 考勤补录
  SALARY_ADJUSTMENT = 'salary_adjustment', // 调薪申请
  CONTRACT_RENEWAL = 'contract_renewal',     // 合同续签
  SALARY_BUDGET = 'salary_budget',         // 工资预算
  TRANSFER = 'transfer',                   // 转岗申请
}

export enum ApprovalStatus {
  PENDING = 'pending',       // 待审批
  APPROVED = 'approved',     // 已通过
  REJECTED = 'rejected',     // 已拒绝
  CANCELLED = 'cancelled',   // 已取消
}

export enum ApprovalCategory {
  HR = 'hr',           // HR审批
  BUSINESS = 'business', // 业务审批
  QUALITY = 'quality',  // 质量审批
}
```

### 3.2 审批接口定义

```typescript
export interface Approval {
  id: string;
  code: string;                    // 审批单编号 SP-YYYYMMDD-XXX
```
