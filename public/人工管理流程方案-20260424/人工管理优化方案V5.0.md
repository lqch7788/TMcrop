## 一、项目背景与目标

### 1.1 项目背景

人工管理模块是种植管理系统的重要组成部分，涵盖了从员工入职到离职的完整生命周期管理。当前模块存在以下问题：

1. **数据孤岛问题**：临时工和正式员工数据分离，各子模块数据无法共享
2. **硬编码严重**：HrApprovalDocuments、HrAttendance等页面存在大量硬编码数据
3. **业务流程断裂**：请假/加班申请与审批流程未完全打通
4. **组件重复**：批量编辑、导出、分页等组件在每个模块重复实现
5. **HR审批单功能缺失**：新增、编辑、查看按钮无实际功能

### 1.2 项目目标

本次优化的核心目标是：

1. **数据连通**：建立统一的员工主数据模型，实现各模块数据共享
2. **流程顺通**：梳理并打通从入职到离职的完整业务流程
3. **体验优化**：统一组件设计，提升用户体验
4. **业务闭环**：实现请假/加班/调岗/离职等业务的完整审批闭环

### 1.3 目标用户

| 用户角色 | 代码 | 需求描述 |
|---------|------|---------|
| **普通员工** | EMPLOYEE | 提交请假/加班申请、查看工资、查看考勤记录 |
| **班组长** | TEAM_LEADER | 查看组员考勤、审批组员申请、安排排班 |
| **人事专员** | HR | 员工入职办理、合同管理、HR审批 |
| **人事经理** | HR_MANAGER | 部门人事管理、薪资核算、报表分析 |
| **系统管理员** | ADMIN | 部门/岗位配置、权限管理、系统设置 |
| **财务人员** | FINANCE | 工资发放、社保公积金核算 |

## 二、现有问题深入分析

### 2.1 HR审批单页面详细分析

#### 2.1.1 HrApproval.tsx 页面分析

**表格字段：**

| 字段 | 数据类型 | 数据来源 | 问题 |
|------|----------|----------|------|
| code | string | Approval.code | 正常 |
| applicantName | string | Approval.applicantName | 正常 |
| type | ApprovalType | Approval.type | 正常 |
| applyDate | string | Approval.applyDate | 正常 |
| status | ApprovalStatus | Approval.status | 正常 |
| id | string | Approval.id | 正常 |

**问题：**
- 查看按钮仅有UI无实际跳转逻辑
- 审批操作通过/拒绝无确认弹窗
- 状态筛选缺少"已拒绝"选项

**数据流：**
```
ApprovalContext (localStorage持久化)
    ↓ useHrApprovals() hook
    ↓ 过滤: category === 'hr'
    ↓ 按type再分类: LEAVE/OVERTIME/TRANSFER/RESIGN
HrApproval.tsx
```

#### 2.1.2 HrApprovalDocuments.tsx 页面分析

**表格字段：**

| 字段 | 数据类型 | 数据来源 | 问题 |
|------|----------|----------|------|

### 2.2 数据孤岛问题

| 孤岛页面 | 问题描述 | 联动影响 |
|---------|---------|---------|
| LeavePage | 请假数据独立，不经过审批系统 | 考勤系统无法获取已批假数据 |
| OvertimePage | 加班数据独立，不经过审批系统 | 工资系统无法获取加班数据 |
| RecruitmentPage | 招聘申请独立，无审批流程 | 入职流程无法触发 |
| HrApprovalDocuments | 考勤单据独立数据源 | 与LeavePage/OvertimePage数据不同步 |

### 2.3 员工ID体系混乱

| 格式 | 来源 | 问题 |
|-----|------|-----|
| S001/S002 | LeavePage, OvertimePage | 不统一 |
| W001/W002 | 其他页面 | 不统一 |
| EMP001/EMP002 | 员工档案 | 标准格式 |

**解决方案**: 统一为 `EMP-YYYYMMDD-XXX` 格式

```typescript
export enum ApprovalType {
  LEAVE = 'leave',                           // 请假申请

  SALARY_BUDGET = 'salary_budget',           // 工资预算
  TRANSFER = 'transfer',                     // 转岗申请
}

export enum ApprovalStatus {
  PENDING = 'pending',       // 待审批
  APPROVED = 'approved',     // 已通过
  REJECTED = 'rejected',     // 已拒绝
  CANCELLED = 'cancelled',   // 已取消
}

export enum ApprovalCategory {
  HR = 'hr',           // HR审批

}
```

### 7.6 工资计算数据流

```
[工资计算触发（月末）]
  │
  ↓
[获取计算参数]
  ├── 计算周期：YYYY-MM
  └── 应出勤天数：从日历表获取
  │
  ↓
[获取员工列表]
  └── 查询 employees 表 (status != 'resigned')
  │
  ↓
[对每个员工计算工资]
  │
  ├── [1] 获取薪酬标准
  │   └── 查询 contracts 表 → monthly_salary
  │
  ├── [2] 获取考勤数据
  │   └── 查询 attendance_records 表
  │       ├── COUNT(status='normal') → 出勤天数
  │       ├── COUNT(status='late') → 迟到次数
  │       ├── COUNT(status='absent') → 缺勤天数
  │       └── SUM(late_minutes) → 迟到总分钟
  │
  ├── [3] 获取加班数据
  │   └── 查询 overtime_records 表
  │       └── SUM(total_hours) → 加班总时长
  │
  ├── [4] 获取请假数据
  │   └── 查询 leave_records 表
  │       └── SUM(total_days) → 请假总天数
  │
  ├── [5] 获取计件数据
  │   └── 查询 piecework_records 表
  │       └── SUM(piecework_amount) → 计件总额
  │
  ├── [6] 计算应发项目
  │   ├── base_salary = monthly_salary / 应出勤天数 × 出勤天数
  │   ├── overtime_pay = 加班时长 × 时薪 × 加班系数
  │   ├── piecework_pay = 计件总额
  │   ├── attendance_bonus = 无迟到早退缺勤 ? 满勤奖标准 : 0
  │   └── gross_pay = base + overtime + piecework + bonus + allowances
  │
  ├── [7] 计算扣款项目
  │   ├── leave_deduction = 请假天数 × 日薪 × 扣款系数
  │   ├── late_deduction = 迟到次数 × 扣款标准
  │   ├── absent_deduction = 缺勤天数 × 日薪
  │   ├── social_insurance = 工资基数 × 社保比例
  │   └── total_deduction = SUM(各项扣款)
  │
  ├── [8] 计算实发工资
  │   └── net_pay = gross_pay - total_deduction
  │
  └── [9] 保存工资记录
      └── INSERT INTO salary_records 表
  │
  ↓
[生成工资汇总表]
  └── 按部门/班组汇总
  │
  ↓
[提交审批]
  └── 创建工资审批单 → approvals 表
  │
  ↓
[审批通过]
  │
  └── 更新工资状态 → salary_records 表 (status='approved')
  │
  ↓
[工资发放]
  │
  └── 更新发放状态 → salary_records 表 (pay_status='paid')
```

```
  ↓
```

**联动引擎接口设计:**

```typescript
interface ApprovalBusinessBridge {
  // 识别审批类型并执行联动
  execute(type: ApprovalType, businessData: BusinessData): Promise<BridgeResult>;

  // 获取联动规则
  getBridgeRule(type: ApprovalType): BridgeRule;

  // 记录联动日志
  logBridgeExecution(execution: BridgeExecution): void;
}

interface BridgeRule {
  type: ApprovalType;
  targetTable: string;
  operation: 'INSERT' | 'UPDATE' | 'DELETE';
  validationFn?: (data: BusinessData) => boolean;
  preExecuteFn?: (data: BusinessData) => Promise<void>;
  executeFn: (data: BusinessData) => Promise<void>;
  postExecuteFn?: (data: BusinessData) => Promise<void>;
  notificationFn?: (data: BusinessData) => Promise<void>;
}
```
