> 制定日期：2026-04-25
> 制定人：Planner Agent
> 版本：v1.0

## 一、现有问题总结

### 1.1 数据层问题

| 问题 | 严重程度 | 影响 |
|------|---------|------|
| 大量硬编码数据 | HIGH | HrApprovalDocuments、HrAttendance、LeavePage等页面的mock数据直接写在组件内 |
| 员工选择手动输入 | HIGH | LeavePage的员工姓名是手动输入而非下拉选择 |
| 员工数据未统一 | HIGH | 临时工和正式员工数据分离，无法共享 |
| 数据持久化缺失 | MEDIUM | 页面刷新后数据重置 |
| 状态类型不统一 | MEDIUM | 不同模块状态枚举值定义分散 |

### 1.2 业务层问题

| 问题 | 严重程度 | 影响 |
|------|---------|------|
| 请假余额未校验 | HIGH | 提交时未检查假期余额是否充足 |
| 加班费计算不透明 | MEDIUM | 时薪未设置，显示不清晰 |
| 审批流程未指定审批人 | HIGH | 审批人未明确指定 |
| HR审批单页面功能缺失 | HIGH | 新增、编辑、查看按钮无功能 |

### 1.3 组件层问题

| 问题 | 严重程度 | 影响 |
|------|---------|------|
| 代码重复严重 | HIGH | 导出Excel/CSV逻辑、状态徽章、分页组件在每个模块重复 |
| 批量编辑弹窗不一致 | MEDIUM | 不同模块布局差异大 |
| 类型定义分散 | MEDIUM | 状态类型不统一，分散在各个types.ts |

## 三、模块间数据关联

### 3.1 核心关联关系

| 关联 | 关系类型 | 说明 |
|------|---------|------|
| Worker ↔ Department | N:1 | 员工属于部门 |
| Worker ↔ Position | N:1 | 员工担任岗位 |
| Worker ↔ Team | N:1 | 员工属于班组 |
| Worker ↔ Contract | 1:N | 员工有多份合同 |
| Worker ↔ Schedule | 1:N | 员工有多条排班记录 |
| Worker ↔ Attendance | 1:N | 员工有多条考勤记录 |
| Worker ↔ Leave | 1:N | 员工有多条请假记录 |
| Worker ↔ LeaveQuota | 1:N | 每种假期类型有一个余额 |
| Worker ↔ Overtime | 1:N | 员工有多条加班记录 |
| Worker ↔ Salary | 1:N | 员工有多月工资记录 |
| Leave → Approval | 1:1 | 请假关联一个审批单 |
| Overtime → Approval | 1:1 | 加班关联一个审批单 |

### 3.2 数据流转设计

#### 请假申请数据流

```
1. 员工选择请假类型和日期
   ↓
2. 系统校验假期余额 (查询 LeaveQuota)
   ↓
3. 系统带出员工信息和可用审批人
   ↓
4. 员工填写请假申请表单
   ↓
5. 创建 Leave 记录 (status: '待审批')
   ↓
6. 自动创建 Approval 审批记录
   ↓
7. 通知审批人
   ↓
8. 审批人审批 (通过/驳回)
   ↓
9. 更新 Leave.status
   ↓
10. 更新 LeaveQuota (冻结/扣减余额)
   ↓
11. 同步到考勤系统
```

#### 加班申请数据流

```
1. 员工选择加班日期和时间段
   ↓
2. 系统自动获取员工时薪 (Worker.hourlyRate)
   ↓
3. 系统计算加班费 = hours × hourlyRate × payMultiplier
   ↓
4. 员工填写加班原因
   ↓
5. 创建 Overtime 记录
   ↓
6. 自动创建 Approval 审批记录
   ↓
7. 审批通过后，更新 Overtime.status
   ↓
8. 加班费汇总到 Salary 月度工资
```

## 四、业务流程梳理

### 4.1 入职流程

```
[Start] 入职申请
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 基础信息录入 - 姓名、身份证、联系电话、出生日期、性别      │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 任职信息录入 - 部门、岗位、用工类型、入职日期              │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 薪资信息录入 - 薪资类型、基本工资金额                      │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 合同信息录入 - 合同类型、合同期限                         │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  5. 审批流程 - 人事专员初审 → 人事经理复审                     │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  6. 入职办理完成 - Worker.status='在职'，创建假期余额          │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 请假/加班审批流程

```
员工提交申请
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  前置校验                                                     │
│  - 请假余额是否充足 (LeaveQuota)                              │
│  - 是否超过最大连续请假天数                                    │
│  - 加班日期是否与已有排班冲突                                 │
│  - 时薪是否已设置 (加班费计算用)                              │
└─────────────────────────────────────────────────────────────┘
    │
    ▼ (校验通过)
┌─────────────────────────────────────────────────────────────┐
│  创建业务记录 + 审批记录                                      │
│  - Leave/Overtime (status: '待审批')                        │
│  - Approval (currentStep: 1, status: 'pending')             │
│  - LeaveQuota (pendingDays += 申请天数)  ← 冻结余额         │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  审批流程执行                                                 │
│  Step 1: 直接主管审批                                        │
│          ├─ 通过 → Step 2 / 最终通过                         │
│          └─ 驳回 → 申请被拒绝                                │
│                                                             │
│  Step 2: 人事审批 (请假>3天/加班>4小时)                     │
│          ├─ 通过 → 最终通过                                   │
│          └─ 驳回 → 申请被拒绝                                │
└─────────────────────────────────────────────────────────────┘
    │
    ▼ (审批通过)
┌─────────────────────────────────────────────────────────────┐
│  结果处理                                                     │
│  Leave: status='已审批'，LeaveQuota扣减                     │
│  Overtime: status='已审批'，加班费汇总到次月Salary           │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 薪酬发放流程

```
[每月1日] 上月考勤数据汇总
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 考勤数据同步                                             │
│     - Attendance → 月度汇总                                  │
│     - Leave (已审批) → 请假扣款                             │
│     - Overtime (已审批) → 加班费                            │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 工资计算                                                 │
│     月薪制: 应发 = 基本工资 + 岗位工资 + 加班费 + 奖金        │
│     日薪制: 应发 = 日薪 × 出勤天数 + 加班费                   │
│     时薪制: 应发 = 时薪 × 实际工时 + 加班费                   │
│     实发 = 应发 - 社保个人 - 公积金个人 - 个税 - 扣款          │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 工资确认 - 生成Salary记录，推送员工确认                   │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 财务发放 - status='已发放'                               │
└─────────────────────────────────────────────────────────────┘
```

## 六、弹窗和表单设计

### 6.1 请假申请弹窗 (LeaveFormModal)

| 字段 | 控件类型 | 校验规则 | 说明 |
|------|---------|---------|------|
| 员工姓名 | 下拉选择 | 必填，从Worker列表选择 | 显示工号和姓名 |
| 请假类型 | 下拉选择 | 必填 | LeaveType枚举 |
| 开始日期 | 日期选择器 | 必填，不能早于今天 | YYYY-MM-DD |
| 结束日期 | 日期选择器 | 必填，不能早于开始日期 | YYYY-MM-DD |

## 八、关键决策记录 (ADR)

### ADR-001: 员工数据统一方案

**决策：** 建立统一的Worker主数据模型，各模块共享使用

**驱动因素：**
1. 当前临时工和正式员工数据分离
2. 请假、加班等模块无法获取完整员工列表
3. 员工选择采用手动输入容易出错

**决策结果：**
- 创建src/types/labor/worker.ts统一类型
- 创建src/services/workerService.ts数据服务
- 各模块通过服务获取员工数据，不再独立存储

### ADR-002: 批量编辑组件统一方案

**决策：** 开发通用BatchEditModal组件，所有模块复用

**决策结果：**
- 开发可配置的BatchEditModal组件
- 支持字段选择、预览、上一条/保存操作
- 各模块通过参数配置使用

### ADR-003: 审批流程配置方案

**决策：** 采用配置化审批流程，支持按条件自动指定审批人

**决策结果：**
- 创建approval_workflow配置表
- 支持按部门、岗位、金额等条件配置
- 申请提交时自动根据配置指定审批人
