## 一、现有模块现状与关联分析

### 1.1 人工管理现有四个子菜单

| 模块 | 文件 | 核心功能 | 现状问题 |
|------|------|----------|----------|
| 任务工单 | Tasks.tsx | 任务创建/筛选/状态管理 | 与TaskDispatch重复，缺少工时统计 |
| 工人考勤 | WorkerAttendance.tsx | 考勤记录/导出 | 仅记录，缺少请假/加班申请流程 |
| 工作日志 | WorkLog.tsx | 日报记录/问题反馈 | 手工录入，缺少照片上传、问题跟踪闭环 |
| 工作月报 | MonthlyReport.tsx | 月度汇总统计/导出 | 手工生成，缺少自动汇总和对比分析 |

### 1.2 农业人工管理五大核心痛点

```
农业人工管理五大核心痛点：
1. 季节性波动 → 农忙/农闲时期人员需求差异大
2. 临时工管理 → 短期工、季节工快速招募和结算
3. 技能要求多样 → 不同工序需要不同技能（授粉/施肥/采收）
4. 工时统计复杂 → 露天作业受天气影响，实际与计划偏差大
5. 安全风险高 → 农药使用、机械操作存在安全隐患
```

#### 模块2: 排班调度中心 (Scheduling Center) - 升级TaskDispatch

**核心功能**:

| 功能点 | 描述 |
|--------|------|
| 排班日历 | 月/周/日视图展示排班情况 |
| 班次设置 | 早班07:00-15:00/中班15:00-23:00/晚班23:00-07:00 |
| 排班规则 | 设置倒班规则(两班倒/三班倒/弹性排班) |
| 临时调班 | 员工间调班申请与审批 |
| 代班管理 | 请假时代班安排 |
| 排班冲突检测 | 自动检测人员重叠/空缺 |
| 智能推荐 | 基于工人技能和位置推荐最佳人选 |
| 排班导出 | 生成月度排班表导出 |

**排班类型**（借鉴opencode）:

| 排班类型 | 说明 | 适用人群 |
|----------|------|----------|
| 正常班 | 固定时间上下班 | 正式员工 |
| 两班倒 | 早班/晚班 | 棚内作业 |
| 三班倒 | 早/中/晚班 | 连续作业 |
| 弹性班 | 时间弹性 | 管理人员 |
| 临时班 | 短期任务安排 | 临时工 |

**排班规则配置**（借鉴opencode）:

```javascript
// 排班规则配置
{
  "maxContinuousDays": 6,      // 最多连续工作6天
  "minRestHours": 8,           // 最少休息8小时
  "rotateInterval": 7,         // 班组轮换周期（天）
  "holidayReplacement": true,  // 节假日是否换班
  "overtimeLimit": 40,         // 月加班上限（小时）
  "nightAllowance": 20         // 夜班补贴（元/天）
}
```

**排班冲突检测**（借鉴opencode）:

| 冲突类型 | 检测规则 | 处理方式 |
|----------|----------|----------|
| 人员重复 | 同一人员不能同时安排两个班次 | 提示并阻止 |
| 超时工作 | 超出月加班上限 | 提示并阻止 |
| 连续工作 | 超出最多连续工作天数 | 警告 |
| 资质不符 | 特种作业无对应资质 | 提示并阻止 |
| 请假冲突 | 与已请假日期冲突 | 提示并阻止 |

**数据结构设计**:
```typescript
interface Schedule {
  id: string;
  scheduleCode: string;
  scheduleDate: string;        // 排班日期
  shiftType: 'morning' | 'afternoon' | 'night' | 'whole_day';
  shiftStart: string;          // 上班时间
  shiftEnd: string;            // 下班时间
  workers: {
    workerId: string;
    workZone: string;          // 作业区域
    task?: string;             // 预分配任务
  }[];
  createdBy: string;
  createdAt: string;
  status: 'draft' | 'published' | 'cancelled';

interface ShiftSwap {
  id: string;
  requesterId: string;         // 申请调班人
  targetId: string;             // 被调班人
  originalScheduleId: string;
  targetScheduleId: string;
  reason: string;
  status: 'pending' | 'approved' | 'rejected';
}
```

**关键关联**:
```
TaskDispatch.tsx ──→ 排班调度 ──→ 任务工单创建
                          │
                          └── 考勤数据 ← 实际出勤记录
```

#### 模块4: 工资管理 (Salary Management) - 新增

**核心功能**: 工资核算与发放管理

**工资结构**（借鉴opencode）:

```
月度工资 = 基本工资 + 岗位工资 + 绩效工资 + 加班费 + 补贴 - 扣款
             │           │          │          │       │
             │           │          │          │       └── 迟到/早退/旷工/损坏
             │           │          │          └── 工作日/周末/节假日
             │           │          └── 按任务完成率
             │           └── 技能等级
             └── 合同约定
```

**工资计算规则**:

```
正式员工:
  应发工资 = 基本工资 + 岗位工资 + 工龄工资 + 加班费 + 全勤奖 + 绩效奖金 - 缺勤扣款 - 社保 - 公积金 - 个税

临时工:
  应发工资 = 出勤天数 × 日工资  或  实际工时 × 时工资
```

**临时工结算方式**（借鉴opencode）:

| 结算方式 | 说明 | 计算公式 |
|----------|------|----------|
| 日结 | 按天计算 | 日薪 × 出勤天数 |
| 计件 | 按量计算 | 单价 × 完成数量 |
| 月结 | 按月计算 | 月薪 / 月标准工时 × 实际工时 |

**扣款项目**（借鉴opencode）:

| 扣款类型 | 计算方式 | 说明 |
|----------|----------|------|
| 迟到 | 固定金额/次 | 如：20元/次 |
| 早退 | 固定金额/次 | 如：20元/次 |
| 旷工 | 日薪倍数 | 如：扣3倍日薪 |
| 损坏 | 实际价值 | 物料/设备损坏赔偿 |

**考勤规则配置**（借鉴opencode）:

```javascript
// 考勤规则配置示例
{
  "workHours": {
    "morning": { "start": "07:00", "end": "11:00" },
    "afternoon": { "start": "13:00", "end": "17:00" },
    "evening": { "start": "18:00", "end": "21:00" }
  },
  "lateThreshold": 30,        // 迟到30分钟算迟到
  "earlyLeaveThreshold": 30,  // 早退30分钟算早退
  "absentThreshold": 240,     // 旷工240分钟算旷工
  "overtimeRate": 1.5,       // 加班费倍率
  "holidayRate": 2.0          // 节假日工资倍率
}
```

**功能模块**:

| 功能模块 | 描述 |
|----------|------|
| 工资项配置 | 基本工资/岗位工资/工龄工资/加班费/全勤奖/绩效奖金/扣款项 |
| 计件工资 | 按采收量/种植面积等计件结算 |
| 月度工资单 | 自动汇总考勤/任务/请假生成工资单 |
| 临时工结算 | 按日/按件快速结算 |
| 工资条发放 | 员工查看个人工资条 |
| 批量发放确认 | 财务确认发放 |
| 个税申报 | 自动计算代扣个税 |

**工单生命周期**（借鉴opencode）:
```

 │      │      │      │      │      │

 │      │      │      │      └── 质量验收
 │      │      │      └── 执行中（可暂停）
 │      │      └── 工人确认接单
```

**派工决策因素**:

| 因素 | 权重 | 数据来源 |

| 历史表现 | 15% | 任务完成记录 |
| 紧急程度 | 10% | 任务优先级 |

**派工算法**:
```
Score(worker, task) = Σ(factor_i × weight_i)

推荐Top3候选人，供主管确认
```

   - 正式员工：考勤数据 → 加班费计算 → 工资单生成

   - 扣款规则（迟到/早退/旷工）验证

   - 任务执行 → 完成确认 → 工时统计
   - 智能派工推荐 → 一键确认派工
