# 人工管理模块菜单合并与深度整合优化方案

> **规划版本**: V3.0
> **规划日期**: 2026-04-04
> **当前系统版本**: V1.01 (hongzhiyun)
> **规划状态**: 待用户确认

---

## 一、现状分析

### 1.1 当前问题

- 人工管理模块有 **20 个子菜单**，菜单过于分散
- 功能模块之间缺乏流程串联
- 与农事管理等其他模块的数据对接不清晰

### 1.2 现有组件化资产

大部分业务逻辑已下沉到 `src/components/labor/` 下的 Hooks 中，pages/ 下的文件大多是高5-10行的薄封装。

## 二、优化后的菜单结构（5合1）

### 2.1 五合一菜单重组

```
人工管理 (Users)
├── 人事管理 (Personnel)
│   ├── 招聘管理        (/labor/personnel?tab=recruitment)
│   ├── 入职办理        (/labor/personnel?tab=onboarding)
│   ├── 员工档案        (/labor/personnel?tab=archive)
│   ├── 合同管理        (/labor/personnel?tab=contract)
│   └── 班组分配        (/labor/personnel?tab=team)
│
├── 考勤管理 (Attendance)
│   ├── 排班调度中心    (/labor/attendance?tab=schedule)
│   ├── 工人考勤        (/labor/attendance?tab=attendance)
│   ├── 请假管理        (/labor/attendance?tab=leave)
│   └── 加班管理        (/labor/attendance?tab=overtime)
│
├── 任务管理 (Task)
│   ├── 任务工单        (/labor/task?tab=tasks)
│   ├── 智能派工        (/labor/task?tab=dispatch)
│   └── 工作日志        (/labor/task?tab=worklog)
│
├── 薪酬管理 (Compensation)
│   ├── 工资管理        (/labor/compensation?tab=salary)
│   ├── 计件工资        (/labor/compensation?tab=piecework)
│   └── 工资预算        (/labor/compensation?tab=budget)
│
└── 运营分析 (Analytics)
    ├── 绩效考核        (/labor/analytics?tab=performance)
    ├── 工作月报        (/labor/analytics?tab=monthly)
    ├── 人效分析        (/labor/analytics?tab=efficiency)
    └── 劳动风险预警    (/labor/analytics?tab=risk)
```

### 2.2 路由设计

```
/labor/personnel        → 人事管理（默认 Tab: recruitment）
/labor/attendance      → 考勤管理（默认 Tab: schedule）
/labor/task            → 任务管理（默认 Tab: tasks）
/labor/compensation     → 薪酬管理（默认 Tab: salary）
/labor/analytics       → 运营分析（默认 Tab: performance）
```

### 4.2 农事任务派发与人工管理对接

```
农事任务派发 (TaskDispatch)
    │
    ├── 选择地块+作物+工序 ───▶ 关联计件工序表
    ├── 选择执行班组 ─────────▶ 从[班组分配]获取班组及成员
    ├── 生成任务工单 ─────────▶ 写入[任务工单]
    ├── 自动排班 ─────────────▶ 写入[排班调度中心]
    ├── 执行结果记录 ──────────▶ 写入[工作日志]
    └── 考勤数据同步 ─────────▶ 写入[工人考勤]
                                    │
                                    ▼
                            计入[计件工资]和[工资管理]
```

### 4.3 采收入库与考勤、工资对接

```
采收入库 (Harvest)
    │
    ├── 记录采收人员 ─────────▶ 从[员工档案]获取
    ├── 记录工时 ─────────────▶ 写入[工人考勤]
    └── 记录产量 ─────────────▶ 计入[计件工资]
                                      │
                                      ▼
                              [工资管理] 月末汇总
```

### 5.2 核心组件设计

#### LaborTabNav.tsx — 统一左侧Tab组件

```tsx
interface TabItem {
  key: string;
  label: string;
  icon?: React.ComponentType;
  badge?: number | string;
}

interface LaborTabNavProps {
  tabs: TabItem[];
  activeTab: string;
  onTabChange: (key: string) => void;
}
```

#### PersonnelPage.tsx — 人事管理容器

```tsx
export function PersonnelPage() {
  const { tab: activeTab, setTab } = useSearchParams();
  const tabs = [
    { key: 'recruitment', label: '招聘管理', icon: UserPlus },
    { key: 'onboarding', label: '入职办理', icon: ClipboardCheck },
    { key: 'archive', label: '员工档案', icon: FileText },
    { key: 'contract', label: '合同管理', icon: FileSignature },
    { key: 'team', label: '班组分配', icon: Users },
  ];

  return (
    <LaborLayout>
      <LaborTabNav tabs={tabs} activeTab={activeTab || 'recruitment'} onTabChange={setTab} />
      <div className="flex-1">
        {activeTab === 'recruitment' && <RecruitmentTable />}
        {activeTab === 'onboarding' && <OnboardingTable />}
        {activeTab === 'archive' && <ArchiveTable />}
        {activeTab === 'contract' && <ContractTable />}
        {activeTab === 'team' && <TeamTable />}
      </div>
    </LaborLayout>
  );
}
```

## 九、核心设计原则

1. **Tab状态URL化**：?tab=xxx 支持书签和分享
2. **容器即页面，旧组件即内容**：不需要重写业务逻辑
3. **零破坏演进**：通过路由重定向平滑过渡
4. **共享组件下沉**：通用组件复用
5. **跨模块数据单点获取**：统一获取班组、员工等共享数据
