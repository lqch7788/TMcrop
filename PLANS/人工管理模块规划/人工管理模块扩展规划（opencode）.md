## 一、背景与目标

### 1.1 现有模块分析

当前人工管理模块包含四个子菜单：

| 子菜单 | 核心功能 | 存在问题 |
|--------|----------|----------|
| 任务工单 | 三种种植模式工单管理 | 与Tasks.tsx重复，缺少任务分配和工时统计 |
| 工人考勤 | 考勤记录查询和导出 | 仅记录考勤，缺少请假/加班申请流程 |
| 工作日志 | 每日工作记录和反馈 | 手工录入，缺少照片上传、问题跟踪闭环 |
| 工作月报 | 月度工作汇总统计 | 手工生成，缺少自动汇总和对比分析 |

### 1.2 农业人工管理的特殊性

```
农业人工管理五大核心痛点：
1. 季节性波动 → 农忙/农闲时期人员需求差异大
2. 临时工管理 → 短期工、季节工快速招募和结算
3. 技能要求多样 → 不同工序需要不同技能（授粉/施肥/采收）
4. 工时统计复杂 → 露天作业受天气影响，实际与计划偏差大
5. 安全风险高 → 农药使用、机械操作存在安全隐患
```

### 1.3 规划目标

```
┌────────────────────────────────────────────────────────────┐
│  总体目标：打造完整的农业人工管理闭环                        │
├────────────────────────────────────────────────────────────┤
│  • 人员信息一体化 → 从入职到离职全生命周期管理              │
│  • 考勤打卡便捷化 → 支持多种打卡方式（GPS/照片）            │
│  • 任务派发精准化 → 根据技能/排班智能分配任务              │
│  • 工时统计自动化 → 实时统计，减少手工汇总                  │
│  • 工资结算透明化 → 计件/计时/日结多种结算方式             │
│  • 培训证书规范化 → 技能档案和证书到期提醒                 │
└────────────────────────────────────────────────────────────┘
```

## 三、详细功能说明

### 3.1 任务工单（优化整合）

#### 3.1.1 工单类型管理

| 工单类型 | 说明 | 关联工序 |
|----------|------|----------|
| 播种工单 | 播种作业 | 整地、播种、覆膜 |
| 施肥工单 | 施肥作业 | 有机肥、化肥、叶面肥 |
| 浇水工单 | 灌溉作业 | 滴灌、漫灌、喷灌 |
| 巡田工单 | 田间巡查 | 病虫害观察、生长记录 |
| 采收工单 | 采收作业 | 采摘、分级、包装 |
| 植保工单 | 病虫害防治 | 打药、熏蒸、生物防治 |
| 整枝工单 | 修剪作业 | 绑蔓、摘心、打杈 |
| 其他工单 | 其他农事 | 遮阳、保温、通风 |

#### 3.1.2 工单生命周期

```
创建 → 派发 → 接收 → 执行 → 验收 → 完成
 │      │      │      │      │      │
 │      │      │      │      │      └── 工时确认/工资结算
 │      │      │      │      └── 质量验收
 │      │      │      └── 执行中（可暂停）
 │      │      └── 工人确认接单
 │      └── 派发给指定工人/班组
 └── 填写工单信息（类型/区域/时间/工作量）
```

#### 3.1.3 工时统计

| 统计维度 | 说明 |
|----------|------|
| 计划工时 | 工单创建时填写 |
| 实际工时 | 工人执行时记录 |
| 偏差分析 | 计划 vs 实际对比 |
| 工时确认 | 工人填报 + 主管审核 |

### 3.2 工人考勤（功能增强）

#### 3.2.1 打卡方式

| 打卡方式 | 适用场景 | 技术实现 |
|----------|----------|----------|
| GPS定位打卡 | 田间作业 | 手机GPS + 范围校验 |

| 设备刷卡 | 固定岗亭 | IC卡/指纹/面容 |
| 手工补录 | 异常情况 | 主管审批后补录 |

#### 3.2.2 考勤规则

```javascript
// 考勤规则配置示例
{
  "workHours": {
    "morning": { "start": "07:00", "end": "11:00" },
    "afternoon": { "start": "13:00", "end": "17:00" },
    "evening": { "start": "18:00", "end": "21:00" }
  },
  "lateThreshold": 30,        // 迟到30分钟算迟到
  "earlyLeaveThreshold": 30,  // 早退30分钟算早退
  "absentThreshold": 240,     // 旷工240分钟算旷工
  "overtimeRate": 1.5,       // 加班费倍率
  "holidayRate": 2.0          // 节假日工资倍率
}
```

| 病假 | 病 | 不限 | 需提供证明 |

### 3.5 排班管理（新增）

#### 3.5.1 排班类型

| 排班类型 | 说明 | 适用人群 |
|----------|------|----------|
| 正常班 | 固定时间上下班 | 正式员工 |
| 两班倒 | 早班/晚班 | 棚内作业 |
| 三班倒 | 早/中/晚班 | 连续作业 |
| 弹性班 | 时间弹性 | 管理人员 |
| 临时班 | 短期任务安排 | 临时工 |

#### 3.5.2 排班规则

```javascript
// 排班规则配置
{
  "maxContinuousDays": 6,      // 最多连续工作6天
  "minRestHours": 8,           // 最少休息8小时
  "rotateInterval": 7,         // 班组轮换周期（天）
  "holidayReplacement": true,  // 节假日是否换班
  "overtimeLimit": 40,         // 月加班上限（小时）
  "nightAllowance": 20         // 夜班补贴（元/天）
}
```

#### 3.5.3 排班冲突检测

| 冲突类型 | 检测规则 | 处理方式 |
|----------|----------|----------|
| 人员重复 | 同一人员不能同时安排两个班次 | 提示并阻止 |
| 超时工作 | 超出月加班上限 | 提示并阻止 |
| 连续工作 | 超出最多连续工作天数 | 警告 |
| 资质不符 | 特种作业无对应资质 | 提示并阻止 |
| 请假冲突 | 与已请假日期冲突 | 提示并阻止 |

### 3.7 工资结算（新增）

#### 3.7.1 工资结构

```
月度工资 = 基本工资 + 岗位工资 + 绩效工资 + 加班费 + 补贴 - 扣款
             │           │          │          │       │
             │           │          │          │       └── 迟到/早退/旷工/损坏
             │           │          │          └── 工作日/周末/节假日
             │           │          └── 按任务完成率
             │           └── 技能等级
             └── 合同约定
```

#### 3.7.2 临时工结算

| 结算方式 | 说明 | 计算公式 |
|----------|------|----------|
| 日结 | 按天计算 | 日薪 × 出勤天数 |
| 计件 | 按量计算 | 单价 × 完成数量 |
| 月结 | 按月计算 | 月薪 / 月标准工时 × 实际工时 |

#### 3.7.3 扣款项目

| 扣款类型 | 计算方式 | 说明 |
|----------|----------|------|
| 迟到 | 固定金额/次 | 如：20元/次 |
| 早退 | 固定金额/次 | 如：20元/次 |
| 旷工 | 日薪倍数 | 如：扣3倍日薪 |
| 损坏 | 实际价值 | 物料/设备损坏赔偿 |

```
│
├── 表格 (Table)
│   ├── 表头：bg-gray-50, text-xs uppercase
│   ├── 斑马纹：hover:bg-primary-50/50
│   └── 状态标签：圆角pill样式
│
├── 表单 (Form)
│   ├── 输入框：rounded-xl, focus:ring-primary-500
│   ├── 选择框：与输入框一致
│   └── 多选标签：pill样式, checked状态
│

│   ├── 标准：h-3, rounded-full
│   └── 渐变：from-primary-400 to-primary-600
│
└── 徽章 (Badge)
    ├── 状态：待处理(黄)、进行中(蓝)、完成(绿)

```

```
└── 交错延迟：stagger-1 ~ stagger-9 (100ms间隔)
```
